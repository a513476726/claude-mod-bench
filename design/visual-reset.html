八个暗色终端方向：前四个收敛，后四个激进。不是网页皮肤：内容按字符格排版，颜色与字重只落到 Claude Code 主题令牌。HTML 只负责本地预览，真正的边界仍是终端。

当前面板把每页放进两张大卡：页签、主卡、分支卡。24 行高的面板里，边界与空行先吃掉一半， 列表只剩 7 行；五行五色又把这 7 行染成五种注意力。

下面的 前四个方向各自回答一个问题：能不能不放框？（A）能不能像数据表？（B） 能不能只留一条脊？（C）能不能让状态自己成列？（D）。 页末的 第二组反过来：状态带（E）、ASCII 海报框（F）、常驻双栏（G）、头条式层级（H）。

每版都给列表页与详情页。宽度可在 80 / 64 / 40 列之间切换，用来检查窄屏； 高度固定为 24 行，这是面板最紧的高度预算。

bench · dock · 80 列 · 现状

两张大卡 + 分支卡。页签 1 行、空行 2 行、卡片边 4 行、分支卡 5 行；24 行里只有 7 行留给列表。

五行五色。每行整行取分区色，扫读前先被颜色分走注意力；干净工作区的分支卡却仍占着固定空间。

框线是唯一的结构。去掉框之后，面板还剩什么？这是所有方向共同要回答的。

A
方向 A · 无框 / 账本

页边 Margin

把面板当账本：没有框，只有页边和横线。

结构
无卡片、无分支卡。分组标题直接落在版面上，组间不空行。
密度
80×24 下 14 条，是现状的两倍。
颜色
只有分组标记与选中行走色；正文与元数据回到灰阶。
签名
左侧 2 格页边：光标、分组标记、折叠箭头都在这一列。

为什么适合暗色

  • 大面积留白与灰阶，颜色只做「分组」与「当前」两件事。
  • 没有背景块，暗色主题下不出现刺眼的实心矩形。
  • 行距与横线承担层级，长时间扫读不累。

代价 / 规范缺口

  • 分组多时靠标题与缩进，不靠框；需要严格的行距。
  • 分支从常驻卡改为页脚摘要 + 下钻，要新交互。
  • UI-SPEC 目前只允许「卡片」一种区域形状；需新增无框布局章节。
  • 列表行不再整行取分区色；需改 §4.3 的颜色规则。
bench · dock · 80 列 · A 页边
B
方向 B · 分组表格 / 键盘流

栅格 Grid

把面板当数据表：一屏看到最多行，选中就是一根实心条。

结构
顶部状态条 + 列头 + 行。分组是内嵌分隔行，分支压成页脚一行。
密度
80×24 下 14 条，且保留分组分隔。
颜色
选中行整行反色；其余只用分组色与状态符号。
签名
反色选中条（accent 背景 + inverse 文字），像 k9s。

为什么适合暗色

  • 一屏只有一个高亮块，视线有确定落点。
  • 列头与分隔线给数据边界，不依赖卡片边框。
  • 键位提示常驻，键盘操作不需要记。

代价 / 规范缺口

  • 反色条在部分主题下可能过亮；必须验证暗/亮主题对比度。
  • 背景色目前只用于页签讨论；需新增「选中行背景」边界。
  • 键位提示必须与实际键位一致（1–4 / z / b），不发明新键。
  • 分支下钻是新页面；需补返回与滚动预算。

C
方向 C · 精修卡片 / 章节

书脊 Spine

保留卡片，但让它像一本书的书脊：一条左脊、上横线、下横线。

结构
区域名在卡外，像章节标题；一条 1 格左脊贯穿内容；上下横线收口。
密度
80×24 下 14 条；分支在 24 行时压成页脚。
颜色
脊线灰阶；选中与分组标记带色；没有背景块。
签名
左脊 + 章节标题：区域仍然有边界，但不再是一个盒子。

为什么适合暗色

  • 灰阶脊线比整圈边框轻，暗色下不抢正文。
  • 章节名在卡外，标题与内容各自有呼吸。
  • 保留「一页一张卡」的心智，改动最小。

代价 / 规范缺口

  • 左脊是逐行竖线，必须由固定宽度容器绘制：内容宽 = 面板宽 − 2，否则 Button / 多 Text 行会错位。
  • ▌ 需 EAW 验证；不稳时回退 |。
  • 卡片标题从边线移到卡外，需补「章节标题」构件与高度预算。
  • 24 行时分支卡不可见，需要「压成页脚」的降级规则。

D
方向 D · 状态优先 / 平铺

标签 Tagged

把状态变成第一列，取消分组标题：一行一个状态词，列表更短。

结构
顶部一行状态筛选轨道；列表按状态排序，每行第一列是 2 字标签。
密度
80×24 下 14 条，还留 3 行呼吸。
颜色
只有状态词带色；其余全部灰阶。
签名
状态词列 + 筛选轨道：分组不再占行，筛选行兼作分组。

为什么适合暗色

  • 颜色集中在一列 8 个词上，暗色下最安静。
  • 没有表头、没有卡片边，24 行几乎全给内容。
  • 状态是显式词语，不用先学 * o ! + .。

代价 / 规范缺口

  • 失去分组折叠；z 需要改为「筛选全部」或移除。
  • 筛选轨道需要点击目标与当前态；窄屏要压缩。
  • 40 列下状态词缩为 1 字（进/待/异/完/无）。
  • 需新增「状态标签列」与「筛选轨道」两节规范。

第二组

四个激进方向

高对比 · 结构性改变

第一组在收敛：去掉框、改分组、加状态列。第二组反过来，用更强的形状改变工作方式—— 实心状态带、ASCII 海报框、常驻双栏、头条式层级。它们都仍然只用字符格、主题色与字重。

E
方向 E · 控制台 / 状态带

仪表盘 HUD

把面板当任务控制台：状态先于列表。

结构
两行反色状态带 + 分段状态条 + 密列表 + 底部 ticker。
密度
80×24 下 14 条；状态带只占 2 行。
颜色
唯一一块实心 accent；其余靠状态条与 meter 的分组色。
签名
常驻仪表带 + ticker：一屏像在值班。

为什么适合暗色

  • 实心带只占两行，是视觉锚点，不铺满整屏。
  • 列表仍以灰阶为主，meter 只是细色块。
  • ticker 把分支与最新时间压到一行，省掉分支卡。

代价 / 规范缺口

  • 背景带在亮色主题下要反转（backgroundColor + inverseText）。
  • ticker 不能动；只做静态截断，不能假装滚动。
  • meter 用 ASCII # / -，不引入块字符。
  • 需新增「状态带 / meter / ticker」三节规范与高度预算。

F
方向 F · ASCII 海报 / 高对比

大字报 Poster

把面板当一张海报：框、状态码、粗 meter。

结构
全宽 # 框；顶部图例；一个展开项；其余为紧凑索引。
密度
80×24 下 1 个展开项 + 12 条索引。
颜色
状态码与 meter 用分组色；# 框保持结构灰阶。
签名
ASCII 框 + 状态码（D3 / R2 / B1 / A7 / N1）。

为什么适合暗色

  • 没有背景块，对比来自字符本身，暗色下非常清楚。
  • 状态码把五个分区压成两个字符，扫读快。
  • 展开项给一条变更足够的存在感，不再是一行里的一格。

代价 / 规范缺口

  • 逐行 # 竖边必须由固定宽度容器绘制（内容宽 = 面板宽 − 4），否则会错位。
  • 40 列下索引名称被截断；详情标题折行，需要单独的窄屏规则。
  • 状态码是新的视觉语言，需要图例与可访问名。
  • 展开项的高度预算固定，索引行数要随高度重算。

G
方向 G · 主从 / 常驻检查器

双栏 Split

把列表和详情放在同一屏：选中即预览。

结构
左 28 格常驻检查器 + 1 格分隔 + 右列表；选中行即时更新左侧，不跳页。
密度
80×24 下右栏 14 条，左栏常驻详情。
颜色
左栏 ▌ accent + 标题 accent；分隔 │ 灰阶。
签名
主从双栏：详情不再是独立页，而是常驻的检查器。

为什么适合暗色

  • 把「列表 → 详情 → 返回」三次跳转压成一次点击。
  • 左栏是持续上下文，右栏保持扫读节奏。
  • 没有背景块；分隔线是唯一的新结构。

代价 / 规范缺口

  • 左栏与分隔必须固定宽度；<56 列退化为单栏。
  • 长标题、长路径在左栏要折行；左栏高度预算固定。
  • 返回层级变化：b 从详情回到列表，而不是关闭一个页面。
  • 需新增「双栏布局 / 常驻检查器 / 窄屏退化」三节规范。

H
方向 H · 编辑式 / 一个头条

头条 Hero

把面板当报纸头版：一件变更占头条，其余进索引。

结构
报头 + 头条（标题 / 元信息 / meter）+ 索引；头条固定占 6 行。
密度
80×24 下 1 个头条 + 12 条索引。
颜色
头条用 accent 标题与 meter；索引只有状态符号色。
签名
一屏一个头条 + 索引：信息有明确的主次。

为什么适合暗色

  • 头条用字号与留白建立层级，不靠背景块。
  • 索引保持灰阶，只有状态符号分散着色。
  • 头版结构让「最新 / 最重要」一眼可见。

代价 / 规范缺口

  • 头条固定占高，索引被压到 12–13 条；高度预算要单独算。
  • 40 列下头条标题折行，索引必须丢列。
  • 头条与索引的选中关系要明确：点索引换头条。
  • 需新增「头条 / 索引」两级层级与高度规则。

先选语言，再谈实现。
安静的重置选 D；结构性的改变选 G。

D 把卡片边框与分组标题换成一行状态筛选，24 行多出 3 行呼吸，颜色只剩 8 个状态词。 它仍然是「列表 + 详情」，改动最小、风险最低；如果分组与折叠是刚需，选 A。

第二组里，G 双栏是最值得做的结构性改变：选中即预览，把「列表 → 详情 → 返回」 压成一次点击。E 是最强的视觉身份，但两行实心状态带与 ticker 要占固定高度， 亮色主题还要反转；F 最像海报，适合做详情页或需要强识别度的场景； H 是头条 + 索引，介于 D 与 F 之间，适合编辑式阅读。

组合也成立：例如「D 的列表 + F 的详情」「G 的双栏 + E 的状态带」「H 的头条 + D 的索引」。
