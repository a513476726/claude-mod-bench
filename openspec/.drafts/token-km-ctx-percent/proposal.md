# 会话 token 单位与上下文占用提醒

> 需求号：待补充
> 需求来源：口述记录（2026-11-18 会话）
> 编写者：zhongzhiguo(www.zzginfo.top)
> 状态：草案（grill-me 产出，`/opsx:propose` 时定稿）

## Why

对话页现在显示的是原始 token 数（如 `入 120000 · 出 8000 · 缓存读 340000 · 缓存写 21000`），既不好扫，也看不出「上下文还能撑多久」。用户需要自己判断何时压缩或清理上下文，但面板没有给出任何可看的信号。把累计值换成 K / M，并新增一个相对**模型真实上下文窗口**的占用百分比（与状态行同源）、按阈值上色，能让「该压缩了」一眼可见；面板关着时，常驻的 AbovePrompt 横条也能看到同一个信号。

## What Changes

1. **会话统计轨道**：四项累计 token 改为 K / M 单位；行尾追加 `CTX 62%`，按阈值上色。
2. **AbovePrompt 横条**：末尾追加 `| CTX 62%`，同一套颜色；宽度不足时先丢「MCP / 对话」，CTX 最后丢；纯文本、不可点。
3. **按模型下钻**：每行与「合计」只做 K / M 格式化，不带百分比（那里的数字是各模型累计，不是上下文占用）。
4. **单轮详情「用量」**：保持不变，仍是精确 token 数值。
5. **数字格式**：<1000 显示原始数（如 `850`）；1000–999 999 显示整数 K（如 `120K`）；≥1 000 000 显示一位小数 M（如 `1.2M`）。
6. **上下文值**：读引擎 `$.session.usage().context`——`tokens`（最后一次响应的输入侧：入 + 缓存读 + 缓存写）÷ `window`（模型的真实上下文窗口）× 100，向下取整。`tokens` 尚未产生时（新会话、刚 compact 完）写 `CTX —`；计算结果 >100 时照写、不截断。
7. **颜色**：<70% 默认灰（muted）；≥70% `warning`；≥90% `error`。

## Non-goals

- 不自行计算上下文占用：不累加 `turn.complete.usage`（文档明确那是本轮所有真实请求之和），也不监听 `turn.step`；口径以引擎 `$.session.usage().context` 为准。
- 不改单轮详情的精确 token，也不在详情里加百分比。
- 不加文字提醒（如「建议压缩」）、按钮、命令或自动压缩 / 清理入口。
- 不引入 emoji 或新字符集；`CTX` 为 ASCII 标签。
- 不改 OpenSpec / MCP / 提示音页签。

## 兼容性约束

- **无 atom / shape 变更**：四项累计仍来自现有 `turns`；`CTX` 直接读引擎，不新增持久状态。
- **引擎能力依赖**：需要 `$.session.usage()`（本机 Claude Code 2.1.317 的二进制已包含 `context_window_size` / `total_input_tokens`）。不带 `breakdown` 的调用按类型文档是免费的、不触发 token 计数；在 `ui.render` 的异步钩子里调用。
- **实时性**：`context` 跟随每次 API 响应更新，进行中的轮次也会变；compaction 后自动回落。与状态行 / OMC 的 ctx 指示器同源，不再另算一套。
- **颜色规则新增一处**：方向 D 目前规定「状态色只落在状态标签与状态轨道」；CTX 的两处（会话轨道、AbovePrompt）需在 `docs/UI-SPEC.md` 与 `.claude/skills/bench-ui/SKILL.md` 中显式列为允许位置。
- **AbovePrompt 现有顺序与宽度行为保留**：`[面板] OpenSpec x/y ◉n !n | MCP n | 对话 n` 之后追加 CTX；CTX 不受现有 `room > 60` 条件约束。
- **窄屏**：轨道先丢 CTX；仍放不下时按实际宽度把 `缓存读 / 缓存写` 缩写为 `读 / 写`，任何宽度都不得溢出。
- 引擎硬约束：见 `docs/SKILL.md`；UI 规范：见 `docs/UI-SPEC.md`。

## 验收标准

| # | 验收项 | 验证方式 |
| --- | --- | --- |
| 1 | 数字格式：`850`、`120K`、`1.2M` 三个区间正确 | 单测覆盖 0 / 999 / 1000 / 999 999 / 1 200 000 |
| 2 | `CTX` 读 `$.session.usage().context`，公式为 `floor(tokens / window × 100)`，含入 + 缓存读 + 缓存写、不含输出 | 单测：注入假 usage；断言与 `tokens/window` 一致 |
| 3 | 阈值：69% muted、70% warning、90% error；计算值 >100 时照写（如 `CTX 235%`） | 单测断言文本与 tone；真机看颜色 |
| 4 | `context.tokens` 缺失（新会话 / 刚 compact）→ `CTX —`，不写 0% | 单测 |
| 5 | 按模型下钻只显示 K/M，页面中不出现 `%` | 单测 |
| 6 | 单轮详情「用量」仍为精确 token | 现有详情测试保持通过 |
| 7 | 窄屏放不下时先丢 CTX，再缩写 `读/写`，不溢出 | 单测（cellsOf）+ PTY 80 / 40 列实测 |
| 8 | AbovePrompt 末尾出现 `| CTX n%` 且同色；先丢 MCP/对话，CTX 最后丢；不可点 | 单测 + PTY 实测 |
| 9 | 面板高度 <20 行时仍显示会话行（含 CTX） | 扩展现有高度用例 |
| 10 | `tsc` 0 错误、`claude plugin test .` 全绿、文档同步 | 三项验证的实际输出 |
