# Design

## Context

见 `proposal.md` 的 Why。当前实现的关键事实：

- Pane 的滚动是引擎对整棵树的窗口：`e.props.scroll.offset` 是窗口第一行，`bodyRows` 是窗口高度；props 不含总行数。总行数只在 `ui.scroll` 事件的 `contentRows` 里（`.claude-plugin/types/claude-code/index.d.ts:12750-12776`、`:15582-15645`）。
- 返回按钮现在由 `backBar()` 画在卡片上边线行内（`hooks/panes.tsx:926-936`），随整棵树滚动移出视口。
- 所有详情页都没有 `height` 限高，正文本身可滚动；问题集中在返回按钮、标题、路径与展示层切片。
- 卡片上边线只有一行，`topEdge()` 用 `endClip` 收尾（`hooks/ui.tsx:69-88`）。
- `wrapCells()` 按显示宽度折行，但整行以空格开头时会丢缩进（`hooks/panes.tsx:970-1019`）。
- 引擎单棵树序列化上限约 100,000 字符、20,000 节点（`index.d.ts:1443`）。

## Goals / Non-Goals

**Goals:**

- 所有带返回页面滚动后返回仍在视口右上角、可点击。
- 超屏时有位置提示；换页回顶部。
- 详情页非表格内容换行展示完整；长标题不再被截断。
- 展示层不再按固定条数/字数切片；存储层截断写明原因。
- 列表页与详情页的行数预算按实际标题行数计算。

**Non-Goals:**

- 不接管 `ui.scroll`（作为真机验证失败后的备选）。
- 不固定标题行与 diff 页签。
- 不提高存储层上限。
- 不改表格行的列宽与截断语义。
- 不改对话详情的折叠预算与「尾部始终可见」承诺（本次按新行为修订 spec，详见 Decisions 7）。

## Decisions

### 1. 返回按钮用 `scroll.offset` 浮动，不接管滚动

**选择**：`screen()` 在所有带返回页面绘制统一 `DetailChrome`；返回浮层 `position: absolute; top = scroll.offset; right = SP.inline + 1`，挂在页面根节点（树的第一行）上。位置提示 `top = scroll.offset + bodyRows - 1`，同样挂在根节点。

**理由**：引擎在 `ui.scroll` 时以新 offset 重跑渲染 hook（`index.d.ts:12761-12767`），浮层的 `top` 跟着窗口移动，视觉上钉在视口顶部/底部；保留引擎原生的方向键、PgUp/PgDn、Home/End、滚轮手感，改动集中在一个组件。

**备选**：

- 接管 `ui.scroll`、把树压成 `bodyRows` 行、自己窗口化：能保证返回独占一行、不压正文，但要自己处理滚动状态、按键、代码块切片与所有详情页的排版，回归面最大。只在真机验证失败时升级。
- 把返回按钮留在卡片上边线：现状，滚动后移出，不满足要求。

**依据**：`docs/UI-SPEC.md` §4.5e（返回按钮）、§4.6（详情布局）；引擎 API 以 `types/claude-code/index.d.ts` 为准。

### 2. 浮层默认 dim、不加背景

**选择**：返回与位置提示沿用 `dimColor`，不加背景色；滚动后浮在正文上，允许压住右上/右下几列。

**理由**：主题令牌没有背景键，硬加 `backgroundColor` 会用近似色，在亮/暗主题下都不可控；先按最小改动落地，真机确认可读性，不可读再升级为固定行或右侧留白。

**依据**：`docs/UI-SPEC.md` §5.2 颜色映射、§4.5e 返回按钮。

### 3. 卡片上边线只放短类别名，完整标题进正文

**选择**：`Card` 的 `title` 改为短类别名（「变更详情」「本轮对话」「调用详情」「文件」「未提交改动」「调用列表」等）；完整标题作为正文第一段，用保留前导空白的宽度折行函数展示。类别名控制在 4 个汉字以内，保证 24 列下不被 `endClip` 截断。

**理由**：卡片边线只有一行，任何长标题都只能截断；把完整标题放进正文，既不改单行边线结构，也不牺牲内容。与用户确认的「标题移入正文」一致。

**备选**：

- 框内多行标题块：保留标题嵌在边线的视觉，但要新增带左边框的标题块、重做卡片结构。
- 标题浮在框外：与卡片脱离，多卡并列时层次混乱。
- 标题可截、正文补全：用户明确否决，标题本身也不允许截断。

**依据**：`docs/UI-SPEC.md` §3.1 区域=卡片、§4.0b Region/Card、§4.6 Detail 详情。

### 4. 新增保留前导空白的折行函数

**选择**：在 `hooks/format.ts` 增加按显示宽度折行且保留行首空格的函数（或修正 `wrapCells` 的前导空白分支），全文页、完整标题、路径都使用它。每行仍按 `cellsOf` 计算宽度，扣掉行首占位。

**理由**：全文页会出现代码、缩进列表；现有 `wrapCells` 在整行前导空格时会丢缩进，直接复用会改变内容。

**备选**：把 `Text` 的 `wrap` 交给引擎；Pane 内 Box 宽度的判断不稳定，且本项目已选择自行排版（`docs/UI-SPEC.md` §4.6「为什么由插件自己折行」）。

**依据**：`docs/UI-SPEC.md` §1.1 字符宽度、§4.6 折行规则。

### 5. 展示层按字符预算取，不再固定条数/字数

**选择**：详情页内容按 `DETAIL_CHAR_BUDGET`（建议 60,000 字符）逐块累计；超出时停止追加，并在末尾写「…还有 N 项未显示（达到显示上限）」。OpenSpec 详情、MCP 详情共用这个预算。

**理由**：引擎单棵树约 100,000 字符，60k 给结构属性留余量；固定 12/160、40/8 是任意切法，既可能切掉重要内容，也不随面板/场景变化。

**备选**：

- 不设预算：大会话/大 MCP 记录会让面板整棵卸载。
- 分批 +「继续显示」按钮：体验更可控，但多一个状态与按钮，本次不需要。
- 只去 12/160，MCP 保留摘要：变更详情全量、MCP 仍不全，规则不一致。

**依据**：`docs/UI-SPEC.md` §3.2 高度预算；引擎 `index.d.ts:1443`。

### 6. 滚动信息用独立 atom，换页统一回顶

**选择**：新增 `view` 之外的滚动信息 atom（`contentRows` + 页面 key），`on('ui.scroll', { requestId: 'bench' })` 写入 `contentRows` 并 `return next(e)`；所有换页动作走统一 `navigate()`，更新 view 后调 `$.ui.scroll({ in: 'bench', to: 'start' })`。

**理由**：`scroll.offset` 与 `bodyRows` 来自 props，`contentRows` 只能从事件拿；页面切换不会自动重置引擎的 offset。统一入口避免每个按钮各写一遍。

**备选**：把 `contentRows` 塞进 view：会与页面状态耦合，且 shape 语义混乱；不重置滚动：从滚到底的列表打开详情会落在详情中间。

**依据**：`docs/UI-SPEC.md` §4.5c 下钻、§4.5e 返回；引擎 `UiScrollInput`。

### 7. 表格行与非表格内容的边界

**选择**：主列表行、diff 文件列表行、对话下钻列表行、分支卡行、提示音开关行属于表格语义，保留固定列宽与截断；其余详情内容一律换行。列表页空态文案改用换行构件。

**理由**：表格依赖固定列宽保持对齐；详情页没有列对齐需求，截断只会藏内容。

**对话详情的尾部可见性**：现有 spec 要求「工具/用量/结束始终可见」。本次不重做折叠预算，改为「折叠后尽量保留；仍超出一屏时可通过滚动与位置提示到达」，并在归档时同步主 spec。这是本次唯一放宽的既有承诺，原因是新的滚动提示与常驻返回让「到达」成为可验证行为。

**依据**：`docs/UI-SPEC.md` §3.3 水平列定义、§4.3 List/Row、§4.6 Detail 详情。

### 8. 存储层截断写明原因与数值

**选择**：`conversation.ts`、`register.tsx`、`files.ts` 在截断处写入「…（已达存储上限 N 字）」或「…（文件超过 60,000 字，已截断）」；不提高现有上限。

**理由**：用户需要区分「换行」与「数据只到这里」；裸 `…` 无法区分。提高上限会放大 store 与树的大小，超出本次范围。

**依据**：`docs/UI-SPEC.md` §4.6 值列换行、§8 反例清单。

## Risks / Trade-offs

- **[浮层超出父级高度时真机可能不可点/不绘制]** → 真机验证是门禁；失败则升级为「接管 `ui.scroll` + 固定返回行」，任务里保留该分支。
- **[dim 浮层压住正文不可读]** → 真机验收；不可读则升级固定行或右侧留白。
- **[Code 页首屏没有 M]** → 按确认的行为：先显示「↑↓ 滚动 · 第 N 行」，首次滚动后补 M；测试覆盖状态切换。
- **[标题移入正文改变视觉层次，行数预算需重算]** → 所有手工切片扣除实际标题行数；24/80 列与长标题测试。
- **[60k 预算仍可能超过引擎序列化上限]** → 用大会话/大 MCP 夹具测试；超限则下调预算，而不是放宽结构性内容。
- **[折行丢失缩进]** → 新增保留前导空白的折行函数并配单测；全文页的代码行必须逐字符保留。
- **[表格行被误改]** → 明确表格清单，测试断言 diff 文件列表仍截断且列对齐。
- **[对话详情尾部可见性被放宽]** → 在 spec delta 与 `UI-SPEC`/`feature` 文档中显式记录，避免被误读为回归。

## 评审修正（2026-11-17，架构师 + UI 设计师）

两轮只读评审后，以下修正纳入实施；与上文 Decisions 冲突时，以本节为准。

### 1. 滚动数据必须真正接线

- `PaneRenderProps.props.scroll` 增加 `offset`；`PaneData` 增加 `scroll: { contentRows, page }`；`PaneActions` 增加 `navigate`。
- `register.tsx` 新增 `scrollInfo` atom（`contentRows` + `page`），`on('ui.scroll', { requestId: 'bench' })` 写入；写失败必须 `catch` 后仍 `return next(e)`，不得冻结滚动；值未变不写 atom，避免双重重绘。
- `navigate()` 覆盖所有换页入口：进详情、返回、切页签、进/出全文、切「变更/整个文件」、`closeFile` / `closeDiff` / `showFile` / `openDiff`，以及 `ui.press` 里的返回处理。导航时清空 `scrollInfo` 的 page key，避免用重绘前的树写入旧值。
- `contentRows` 事件不带 page key，渲染时 `page` 不匹配即视为 0；`N` 必须 `min(N, M)`，避免 N>M。

### 2. 返回浮层的位置与绘制顺序

- 非安静页的树序是「页签 1 + 空行 1 + 卡片上边线」，返回浮层 `top = max(offset, 2)`；安静页 `top = offset`。这样 offset=0 时落在卡片上边线，不会盖页签；滚过页签后才钉在视口顶部。
- `DetailChrome` 必须是页面根节点的**最后一个子元素**，否则会被 `Card` 覆盖（绝对子元素按树序绘制）。
- 位置提示同样最后绘制；`offset=0` 时只覆盖卡片底部边缘/末行，不压页签。

### 3. 类别名与完整标题

- 所有类别名 ≤4 个汉字：`变更` / `本轮` / `列表` / `调用` / `MCP` / `改动` / `文件`；全文页保留 `输入全文` / `回答全文`（4 字，且是 spec 要求的段名）。
- 完整标题进正文：2 格缩进、`INK.accent` 加粗、续行同缩进、不占 `FIELD_COLUMN`；OpenSpec 详情只画一次（不再用 `detailLines[0]` 兼任边线标题）；对话输入段、调用摘要、MCP 服务器名已在正文，不重复。
- diff 文件列表的仓库名只在旧标题里，必须补进正文首段；diff 详情用 `仓库:` / `文件:` 两行字段。

### 4. 位置提示的宽度

- 按 `cellsOf` 分级：`第 N/M 行 · ↑↓ 滚动` → `N/M · ↑↓` → `N/M`；右侧留 3 格；24 列必须放得下。
- N/M 以面板树行计（含页签、空行、卡片边、正文标题），与引擎 `contentRows` 同单位。
- Code 页在 `contentRows` 未知时显示「↑↓ 第 N 行」；首次滚动后补 M。

### 5. 折行函数

- 新增硬折行函数，保留全部字符与前导空白；**不改共享 `wrapCells`**，避免影响 `sectionLine` 等未 trim 的调用。
- 续行缩进与首行一致的正文列；行首占位（缩进、标签列、`│` 位）必须先从宽度里扣掉。
- `wrapCells` 会合并行内连续空格，不足以满足「字符不丢」；全文页使用硬折行。

### 6. 预算按节点/序列化估算

- 60k 字符不足以约束节点数与序列化体积；新增 `DETAIL_SERIAL_BUDGET`（建议 70k 估算值）与 `DETAIL_ROW_BUDGET`（建议 1,500 行）。每行按 `line.length + ceil(cellsOf(line)/width) × 80` 估算序列化开销（行会折成多行，每行都是带 props 的节点），任一预算超限即停止并写「…还有 N 项未显示（达到显示上限）」。
- 详情正文只在被打开时构建：`changeItems` / `callItems` 用 getter 延迟生成 `detailLines`，列表重绘不为每个变更/服务器遍历全部任务与调用。
- diff 源文本也受 60k 字符上限约束，超出时在正文写「…（diff 超过 60,000 字，已截断）」；不得只靠 `isTruncated` 标记。
- 存储上限标记追加在原上限之后；现有 `stats.test.tsx` 的 ≤2001/≤401 断言必须改为「上限 + 标记长度」或 `startsWith` 断言。

### 7. 列表预算与空态

- `available = bodyRows − 4 − 实际标题行数`（页签 1 + 空行 1 + 卡片上下边 2）；`available < 2` 时不手工切片，渲染全部行交给引擎滚动。
- 「…还有 N」按实际展示行数计算，不按旧 `bodyRows` 计算。
- 空态换行允许卡片增长、面板滚动；不得静默截断。24 列长空态用例必须覆盖。

### 8. 测试可观测性

- 先探测测试引擎能否通过 `$.ui.scroll` 或 `on('ui.scroll')` 观测滚动；不能则改为断言渲染结果（返回浮层 `top`、提示文本、换页后的标题）与纯函数单测，并在 tasks 中注明。
- 新增 `hooks/items.test.tsx` 承载展示预算的纯函数测试；1000 条任务/大 MCP 夹具需经 mount 验证节点上限。
- 24 列、5 位行号、长标题、长路径、长空态、缩进续行、Code 首滚后补 M 全部纳入验收。

### 9. UI 设计前置门

- UI 评审、规范产出、UI 实现前 MUST 调用 `frontend-design:frontend-design`；先出设计计划、列规范缺口、补齐 `docs/UI-SPEC.md` / `bench-ui`，再改 UI 代码。
- 终端单字体：`frontend-design` 的字体/配色建议必须映射到 `INK` / `TONE` / `SP` / `cellsOf`，不得引入 hex、新字体或网页式动效。

### 10. 代码评审处置（2026-11-17）

独立 `code-review` 提出 9 项，全部核实并处理：

1. `takeRows` 只按一个节点估算长行 → 现按 `line.length + ceil(cellsOf/width) × 80` 计，宽度由 `drawPane` 传入。
2. 全文页逐行 `cardRow` 补齐 → 全文页行尾不再补空格，只留左侧 `SP.inline`；并按同一显示预算截断，末尾写「还有 N 行未显示」。
3. `contentRows` 未校验 page → 渲染时 page 不匹配按 0；`navigate` 先滚动、后清高度。
4. 已切片的列表仍显示滚动提示 → 只有 `available < 2`（交给引擎滚动）才显示。
5. `available < 2` 时无界渲染 → `listWindow` 上限 200 行，其余写「还有 N」。
6. 估算忽略折行 → 新增 `rowsIn`，会话详情用 `fold` 的 `rows` 估算。
7. 切页签不清 `path` / diff / file → 新增 `navigateTab`，清 `path` 并关闭 diff/file。
8. `toLocaleString()` 受 locale 影响 → 改为固定千分位格式化。
9. 列表每次重绘都构建全部详情 → `detailLines` 改为 getter，只在打开详情时构建。

## Migration Plan

无数据迁移。新增滚动信息 atom 时同步 `types/index.d.ts` 的 `PluginState` 并递增 shape tag；热重载后旧值按 shape 失效，页面重新读取即可。回滚只需撤回本次代码与 atom 定义。

## Open Questions

- 展示预算的具体字符数（建议 60,000）与各页类别标题的最终文案，可在实现与真机验收时微调；不改变行为契约与任务拆分。
