# Proposal

## Why

提示音现在只是四个开关：响或不响，没有画面、没有文字，用户看到声音却不知道是「哪件事结束了」「要决策的是什么」。面板也缺少一个低打扰的常驻反馈点：子代理跑完、一轮开始、会话空闲这些节点，现在没有任何可见信号。

把反馈收拢成一只**宠物**：它在关键节点做动作、发声、并用头顶气泡说一句具体的话。宠物是一个可视化载体，未来其他面板事件（分支切换、异常、上下文压缩、代码审查、优秀实例收集、每日学习等）都可以通过同一个「投喂事件 → 宠物反应」通道接入，而不必每次改动面板布局。

不改的后果：提示音继续是无声的信息（只有声音没有语义）；未来每个新信号都要单独再设计一次通知形态。

## What Changes

- 新增 `宠物` 页签，在面板内以字符像素画呈现一只宠物（使用半块字符 `▀`/`▄` + 前景/背景色，深度为每行半格的像素）。
- 宠物有一套**状态**（空闲 / 思考 / 工作 / 开心 / 需要决策 / 出错 / 睡着）与一套**动作**（眨眼、蹦跳、点头、抖动、转圈）。
- 关键节点触发对应的「表情 + 动作 + 提示音 + 气泡台词」：
  - 一轮任务完成（`turn.complete`，reason=answer）→ 开心 + 蹦跳 + `done` 音 + 「<摘要> 完成啦！」
  - 需要决策（`AskUserQuestion` / 权限询问）→ 需要决策 + 点头 + `decision` 音 + 「需要您决策：<问题首行>」
  - 任务异常（reason=error/aborted/refusal）→ 出错 + 抖动 + `error` 音 + 「出错了：<原因>」
  - 子代理完成 → 开心 + 小跳 + 无音 + 「子任务归队」
  - 一轮开始（用户输入） → 思考 + 转圈 + 无音
- 现有「提示音」页签的开关合并进宠物设置：提示音是否开启、哪几类发声，仍保留在设置页，但默认入口改为点击宠物进入。
- 气泡台词 SHALL 按事件带上具体信息（任务摘要、问题首行、错误原因），而不是固定文案。
- 宠物 SHALL 在空闲超过一段时间后进入「睡着」状态，减少视觉噪音；有新事件即唤醒。

- `pet-companion`: 宠物的外观、状态机、事件反应（动作/表情/气泡/声音）、空闲行为与后续扩展点

## Impact

- 新增模块：`hooks/pet.ts`（纯逻辑：事件 → 反应、状态机、台词）、`hooks/pixel.ts`（像素画定义与半块字符渲染）、`hooks/pet.test.tsx`。
- 代码：`hooks/items.ts`（新增页签 `pet`）、`hooks/panes.tsx`（宠物绘制）、`hooks/register.tsx`（事件接入、声音播放迁移、宠物状态 atom）。
- 类型：`types/index.d.ts` 新增 `PetState` / `PetMood` / `PetReaction` / `PetSettings`；`SoundSettings` 并入 `PetSettings`（**BREAKING**：旧 `sounds` atom 迁移）。
- 文档：`docs/UI-SPEC.md` 新增「宠物」章节与像素画规范；`docs/features/` 新增宠物功能文档。
- 扩展设计（本期只留接口，不实现）：`PetTrigger` 事件通道——见 design.md D4。
