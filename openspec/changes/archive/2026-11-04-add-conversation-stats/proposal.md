# Proposal

## Why

对话页签现在只有「一轮一行」的逐条记录，看不到整场会话的全貌：用了哪些模型、各自花了多少 token（入 / 出 / 缓存读 / 缓存写）、一共调了多少次工具、调了哪些工具、跑了哪些命令。要看这些只能一轮一轮点开，长会话下几乎不可行。

另外，每轮详情里的「工具」行（`Bash ×3 · Write ×4`）只是一行纯文本，没有下钻入口：看不到这 3 次 Bash 分别执行了什么命令，也看不到 Skill 具体展开了哪些技能。用户需要的是「点工具 → 看每次调用 → 点其中一次 → 看完整参数」，逐层深入。

不改的后果：对话页签只能回答「这轮说了什么」，回答不了「这次会话花了多少、做了什么」，而费用与工具使用恰恰是长会话最需要复盘的部分。

## What Changes

- 对话页签顶部新增**会话统计**区：模型与 token 汇总（每个模型一行：入 / 出 / 缓存读 / 缓存写，末尾一行合计）；工具调用总数（按工具名去重后的**种类数**，以及总调用次数）；命令执行总数。
- 统计区中「工具」「命令」两项可点开，进入**下钻列表**：按工具名 / 命令出现的形态分组，每组显示次数，可再点开看每次调用的摘要。
- **逐轮工具下钻**：轮次详情里 `Bash ×3 · Write ×4` 每个工具名变为可点，点开列出该轮该工具的每一次调用（时间、状态、耗时、参数摘要），可再点一次调用看完整参数与结果。
- **Skill 下钻**：`Skill ×N` 点开后列出所调用的技能名与次数，再点开看某个技能在该轮的调用详情。
- 下钻层级至少支持三层：统计 → 工具/命令分组 → 单次调用。

## Capabilities

### New Capabilities
- `conversation-insight`: 对话页签的会话级统计、工具/命令/技能下钻与逐轮工具明细

### Modified Capabilities
- `conversation-log`: 轮次详情的「工具」行由静态文本改为可下钻的入口（行为变化，需 delta）

## Impact

- 状态：`types/index.d.ts` 中 `Turn.tools` 需保留每次调用的明细（新增 `calls: ToolNote[]` 或等价结构），`decisions` atom 递增 shape；新增 `view` 中的下钻栈（`path: string[]`）。
- 代码：`hooks/conversation.ts`（记录调用明细的纯函数）、`hooks/register.tsx`（`tool.call` 写入明细、下钻栈的 press 处理）、`hooks/items.ts`（统计汇总、下钻列表的 Item 生成）、`hooks/panes.tsx`（统计区渲染、可点工具名）。
- 存储：每次调用的摘要文本（Bash 命令一行、Skill 名称）与完整参数需设上限（沿用 `Call` 的 20k / 4k 截断规则），并受 `MAX_TURNS` 约束。
- 文档：`docs/UI-SPEC.md` 新增「会话统计区」与「下钻」章节；`docs/features/conversation/`、`docs/tests/conversation/` 更新。
