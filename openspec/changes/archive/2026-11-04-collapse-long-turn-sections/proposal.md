# Proposal

## Why

一轮对话的详情现在把输入与回答**全量展开**。实际用起来，回忆一轮长对话时（调研、长报告之类），回答往往有上百行，一屏之内只能看到开头，工具、用量、结束原因全被挤到下面，要滚很久。想看全，又只能靠滚动，没有「先看摘要、要看再展开」的路径。

不改的话，对话页越到后面越不好用：真正想比较的两三个字段（用了什么工具、花了多少 token）必须滚过整段回答才能看到。

## What Changes

- 详情页的「输入」与「回答」两段按屏幕高度**折叠显示**：
  - 输入：最多 6 行；
  - 回答：最多占面板高度的一半（`floor(bodyRows × 0.5)` 行，至少 3 行）。
- 超出上限时，在截断处显示一行说明（总行数 / 已显示行数），并给一个「查看全部」按钮。
- **不超就不折**：估算行数没到上限时原样全展，不出现说明行和按钮。
- 「工具 / 用量 / 结束」三节不折叠，任何情况下都可见，不需要滚动就能看到。
- 点「查看全部」进入全屏只读视图，只画这一段的全文，底部「← 返回详情」（`b` 同样返回）；从全屏返回后回到刚才那轮的详情。
- 行数按显示宽度估算（中文占 2 格），跟随窗口宽度变化，不缓存。

### Non-goals

- 不改记录的内容与上限：`Turn` 里存的仍是全文（20,000 字符封顶）。
- 不改列表行：列表仍是一轮一行。
- 不做回答内的搜索、跳转、复制按钮。
- 不改 MCP / OpenSpec / 提示音三个页签的详情。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `conversation-log`: 「对话详情」这条需求的行为改变——输入与回答不再总是全量展开，而是按屏幕高度折叠，并提供查看全文的入口。

## Impact

- `hooks/panes.tsx`：详情绘制按 `bodyRows` 计算折叠行数、渲染说明行与「查看全部」按钮、新增全屏视图。
- `hooks/items.ts`：`detailLines` 保持不截断；新增一个能区分「输入 / 回答」段落的表示，供绘制层折叠（或在 `Item` 上附加段落边界）。
- `hooks/register.tsx`：`view` 状态增加 `fullSection`，`ui.press` 处理「查看全部 / 返回详情」。
- `types/index.d.ts`：`PluginState['bench'].view` 增加字段（shape 从 `view-1` 升到 `view-2`）。
- `hooks/*.test.tsx`：新增折叠、展开、返回的测试。
- `docs/UI-SPEC.md` §9：补折叠规则。
