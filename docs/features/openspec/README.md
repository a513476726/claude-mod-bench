# 变更页签（OpenSpec）

面板第 2 个页签「变更」（快捷键 `2`）：扫描工作区里各仓库的 `openspec/changes/`，把每一处变更平铺成一行，第一列是状态标签，点开看详情。

## 它解决什么

同时开几个仓库做需求时，「哪个变更做到哪了、哪个归档没归档干净」散落在各个目录里，要一个个 `cd` 过去 `cat tasks.md`。这个页签把工作区里所有变更摊在眼前，状态是第一列，按状态一眼扫完。

## 数据从哪来

```
<工作区>/                     ← 工作区根，自身有 openspec/ 时也会扫描
├── .git/
├── openspec/changes/         ← 单仓库形态：会话直接开在仓库里
├── sales-platform/           ← 有 .git 或 openspec/ 就会扫描，名字不限
│   └── openspec/changes/
│       ├── <变更>/
│       │   ├── tasks.md     ← 进度来源：- [x] / - [ ]
│       │   ├── proposal.md  ← 需求号来源
│       │   └── specs/
│       └── archive/
│           └── <日期>-<变更>/
```

- **扫描的仓库**：与分支区共用 `hooks/scan.ts` 的 `discoverOf`——`cwd` 自身、工作区根、以及工作区下每个带 `.git` 或 `openspec/` 的子目录。**不再有仓库名白名单**（详见 [features/branch](../branch/README.md)）。
- **工作区定位**：从 `cwd` 上一级起向上最多 2 层，第一个「装着仓库的目录」即工作区；都没有时取 `cwd` 的上一级。
- **读取失败不清空**：一次扫描读不到会话目录时，页签保留上一次的列表，不会翻成空态。
- **进度**：数 `tasks.md` 里 `- [x]` 与 `- [ ]` 的行数。
- **需求号**：`proposal.md` 里的 `需求号：xxx`。
- **开发**：`git log` 的作者；目录未被 git 跟踪时，取 `git config user.name`。
- **修改时间**：该变更目录下所有文件与一层子目录的最大 mtime。

## 五种状态

状态不再是分段的标题，而是每行第一列的 2 字标签；同一屏最多 5 种标签色，它们共享同一列、同一语义。

| 状态 | 标签 | 条件 | 颜色 |
|---|---|---|---|
| 进行中 | `进行` | 有 tasks.md，未完，未归档 | `claude` |
| 待归档 | `待办` | 有 tasks.md，已全部完成，未归档 | `warning` |
| 归档异常 | `异常` | 已归档但 tasks.md 还有未完成项 | `error` |
| 已归档 | `完成` | 已归档且任务全完成 | `success` |
| 无任务清单 | `无单` | 没有 tasks.md | `subtle` |

- 同一状态内按修改时间降序，最新自然在最上面；不再有额外的「最新」标记。
- 窄屏（<48 列）标签切成 1 字：`进 / 待 / 异 / 完 / 无`。
- 分组折叠与 `z` 快捷键已经移除；筛选统一走状态轨道。

## 状态轨道

```
 全部 14   进行 3   待办 2   异常 1   完成 7   无单 1
```

- 每项都是可点的；计数紧跟标签，muted。
- 点某一状态 → 列表只显示该状态；点 `全部` 清除筛选。
- 整条轨道保持 1 行：宽度不够时从右边丢（`无单 → 完成 → 待办 → 异常 → 进行`），`全部` 最后才丢，保证始终有清除入口。
- <56 列用紧凑形式 `全部14 进行3 待办2 …`（标签与计数之间不留空格）。

## 次要筛选

```
 仓库 全部 · 时间 全部
 仓库 old_sales · 时间 近 7 天        清除
```

- **仓库**：点一次切到下一个仓库，循环回「全部」。
- **时间**：全部 → 今天 → 近 7 天 → 近 30 天 循环。
- 非「全部」的值用 accent；任一筛选生效时出现「清除」，一键回到全部。
- 仓库/时间与状态筛选可以叠加；切换页签、进详情再返回，筛选值不丢。

## 列表行

```
▸ 进行  38/40  00d  bench         detail-page-scroll-and-full-text
  进行  13/16   6d  old_sales     fix-signmanager-full-down-payment
```

```
<光标:2><状态:5><进度:6><时间:5><仓库:14><名称:剩余宽度>
```

- **状态标签**是行内唯一带色的列；进度、时间、仓库用 muted，名称用正文色。
- **进度**写 `38/40`，没有任务清单时写 `—`。
- **时间**按修改时间显示 `00d` / `6d` / `刚刚`；<56 列丢弃。
- **仓库**<64 列丢弃；名称列吸收剩余宽度，尾截断。
- 选中行只加 `▸` 与名称 bold，不改背景、不改标签色。
- 整行可点，打开安静详情页。

## 详情

详情是**安静页**：没有页签、没有状态轨道、没有分支轨道。完整标题按宽度折行（不截断），右上角浮着 `← 返回`；下一行左为状态标签、右为进度：

```
  detail-page-scroll-and-full-text                              ← 返回
  进行                                                38/40
────────────────────────────────────────────────────────────────
仓库    bench
状态    进行中
任务    38/40
需求号  20_20260920001
开发    zhongzhiguo
文件    tasks.md · proposal.md · design.md
修改    11-17 15:44（今天）
归档于  2026-11-10 ※ 仅已归档的变更显示

未完成
1. 补测 _c0 回显
2. …
```

未完成项直接列出 `tasks.md` 的原文，**不固定截到 12 条或每条 160 字**；详情按字符预算取内容，超出时写「… 还有 N 项未显示（达到显示上限）」。内容超屏由面板滚动，`← 返回` 固定在视口右上角，滚到任务末尾仍可点。

## 什么时候刷新

- 会话启动
- 每轮对话结束（`turn.complete`）
- 面板打开期间，**每 5 秒**一次（与分支轨道各用各的周期）

刷新有重入保护，且只在内容签名变化时才写状态——轮询到达不代表变更列表变了。勾选一行 `tasks.md` 后不需要等对话结束，下一个周期就能看到进度与状态变化。
