# OpenSpec 页签

扫描工作区里各仓库的 `openspec/changes/`，把每一处变更按状态分段，一行一条，点开看详情。

## 它解决什么

同时开几个仓库做需求时，「哪个变更做到哪了、哪个归档没归档干净」散落在各个目录里，要一个个 `cd` 过去 `cat tasks.md`。这个页签把工作区里所有变更摊在眼前，按状态排好。

## 数据从哪来

```
<工作区>/                     ← 工作区根，自身有 openspec/ 时也会扫描
├── .git/
├── openspec/changes/         ← 单仓库形态：会话直接开在仓库里
├── sales-platform/           ← 有 .git 或 openspec/ 就会扫描，名字不限
│   └── openspec/changes/
│       ├── <变更>/
│       │   ├── tasks.md     ← 进度来源：- [x] / - [ ]
│       │   ├── proposal.md  ← 需求号来源
│       │   └── specs/
│       └── archive/
│           └── <日期>-<变更>/
```

- **扫描的仓库**：与分支区共用 `hooks/scan.ts` 的 `discoverOf`——`cwd` 自身、工作区根、以及工作区下每个带 `.git` 或 `openspec/` 的子目录。**不再有仓库名白名单**（详见 [features/branch](../branch/README.md)）。
- **工作区定位**：从 `cwd` 上一级起向上最多 2 层，第一个「装着仓库的目录」即工作区；都没有时取 `cwd` 的上一级。
- **读取失败不清空**：一次扫描读不到会话目录时，页签保留上一次的列表，不会翻成空态。
- **进度**：数 `tasks.md` 里 `- [x]` 与 `- [ ]` 的行数。
- **需求号**：`proposal.md` 里的 `需求号：xxx`。
- **开发**：`git log` 的作者；目录未被 git 跟踪时，取 `git config user.name`。
- **修改时间**：该变更目录下所有文件与一层子目录的最大 mtime。

## 五个分段

| 分段 | 条件 | 标记 | 颜色 |
|---|---|---|---|
| 进行中 | 有 tasks.md，未完，未归档 | `*` | `claude` |
| 待归档 | 有 tasks.md，已全部完成，未归档 | `o` | `warning` |
| 归档异常 | 已归档但 tasks.md 还有未完成项 | `!` | `error` |
| 已归档 | 已归档且任务全完成 | `+` | `success` |
| 无任务清单 | 没有 tasks.md | `.` | `subtle` |

分段标题并列成一行：`▾ * 进行中 7   ▸ o 待归档 5   ▸ ! 归档异常 7`。

- **默认只展开「进行中」**，其余四段折叠。
- 点标题切换展开/折叠，折叠时保留标题与计数。
- `z` 全部收起 / 全部展开。
- 折叠/展开不会清零选中位置。

## 页面骨架

整个页签是一张**圆角卡片**，标题嵌在上边线；卡片下方是独立的**分支卡**：

```
◉ [📋 OpenSpec]  [💬 对话]  [🔌 MCP]  [🔊 提示音]

╭─ 📋 OpenSpec ───────────────────────────────────── · 2/12 项 ╮
▾ * 进行中 2   ▸ o 待归档 3   ▸ ! 归档异常 1                
筛选 仓库：全部 | 时间：全部

─────────────────────────────────────────────────────────────
      任务  时间  仓库            名称
─────────────────────────────────────────────────────────────
▸ *     2/9    6d  sales-platform  fix-signmanager-full-…

2/12 项 · 点行看详情                            [ 展开全部 ]  
╰───────────────────────────────────────────────────────────────╯

╭─ 🔀 分支 ────────────────────────────────────────── · 1 个仓库 ╮
* 根目录         main
╰─────────────────────────────────────────────────────────────╯
```

卡内自上而下固定为：**分区栏 → 筛选行 → 空行 → 横线 → 表头 → 横线 → 数据行 → 页脚**。
框线一律灰阶，颜色只留给状态（见 [UI 规范](../../UI-SPEC.md) §3）。

## 列表行

```
<光标:2><进度:6><时间:4><仓库:14><名称:剩余宽度>
▸ *     13/16     6d    old_sales          fix-signmanager-full-down-payment-20260920
```

- **表头与数据行共用同一份列定义**（`LIST_COLS`），列宽随面板宽度计算：名称列吸收剩余，其余固定；**所有列左对齐**。
- 进度右对齐：`13/16` 竖着扫能比较剩余量。
- 仓库中截断（保首尾）——`sales-platform` 与 `sales_platform_web` 差异在中段。
- 名称尾截断，吃掉剩余宽度。
- 最新的变更标 `*`（`warning` 色），归档异常标 `!`（`error` 色），其余为灰。
- 分区标记与名称**不再带 emoji**（旧版的 `⚙️ 进行中` 已移除）；表头也不带 `📝`。

## 详情

详情是**一张独立的卡**，变更名就是卡片标题（前带 `📋`）；字段为两列，标签带 emoji、值从同一列起，**超长自动换行**：

```
╭─ fix-signmanager-full-down-payment-20260920 ────────────────╮
仓库     old_sales                                         
状态     进行中                                            
任务     13/16（欠 3 项）                                  
需求号   20_20260920001                                    
开发     zhongzhiguo                                       
╰─────────────────────────────────────────────────────────────╯
```
文件: tasks.md, proposal.md, design.md
修改: 09-20 14:30（6d前）
未完成 3 项：
  1. 补测 _c0 回显
  2. ...
```

未完成项直接列出 `tasks.md` 的原文（最多 12 条，超过写「还有 N 项」），不只是数量。

## 什么时候刷新

- 会话启动
- 每轮对话结束（`turn.complete`）
- 面板打开期间，**每 5 秒**一次（与分支栏各用各的周期）

刷新有重入保护，且只在内容签名变化时才写状态——轮询到达不代表变更列表变了。勾选一行 `tasks.md` 后不需要等对话结束，下一个周期就能看到进度与分组变化。

## 扫描从哪出发

扫描固定从**会话起始目录**出发，不跟随会话中途的 cwd 变化。分支栏则相反：它跟随实况 cwd，回答的是「我现在在哪」。两者分工是有意的——OpenSpec 回答的是「这个工作区有什么」。

## 列表为空时的三种情况

| 情况 | 显示 |
|---|---|
| 扫到了仓库，但都没有变更 | `还没有读到任何 openspec/changes。` |
| 一个仓库都没扫描（会话目录被标记为搁置的空间等） | `未扫描任何仓库：<原因>` |
| 读取失败 | `（刷新失败，显示上次结果）`，列表保留上一次的内容 |

## 筛选

筛选行在卡片内、分区栏之下：

```
筛选 仓库：全部 | 时间：全部           
```

- **仓库**：在「全部」与扫描到的各仓库之间循环切换
- **时间**：全部 → 今天 → 近 7 天 → 近 30 天 循环切换；「今天」指当天 0 点之后，不是最近 24 小时
- 两项可以叠加；任一生效时多一个「清除」按钮
- 筛选作用于列表，**分段计数随之变化**，没有内容的分段不显示标题
- 筛选条件存在视图状态里：刷新、切换页签都不会被重置
