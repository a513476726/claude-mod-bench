# MCP 审计（会话页下钻）

按 MCP 服务器分组，看本会话里每次调用了什么工具、传了什么参数、成功还是失败、花了多久。MCP 不再占一个顶层页签：入口在**会话页统计轨道**的 `MCP N 次`。

## 它解决什么

MCP 工具调用在终端里只显示一行摘要，参数和结果都被折叠。查「刚才那次 oracle_query 到底传了什么 SQL、为什么失败」时没有好用的地方。这里按服务器归档每次调用。

## 入口与层级

```
会话页统计轨道  ──点 MCP 12 次──▶ 服务器列表（安静页）
                                     └─点服务器──▶ 调用列表（最新在前）
                                                     └─点调用──▶ 完整参数与结果
```

- 每层都是安静页：没有页签、状态轨道与分支轨道；右上角 `← 返回`（`b` 等价）逐层退回；
- 回到会话列表时页签栏恢复；
- 没有任何 MCP 调用时，服务器列表写「本次会话没有 MCP 调用。」。

## 记什么

只记 `mcp__*` 开头的工具调用（内置工具如 `Read`、`Bash` 不进这里）。

每次调用记：

| 字段 | 内容 |
|---|---|
| 时间 | 调用开始时刻 |
| 工具名 | 去掉 `mcp__<server>__` 前缀后的名字 |
| 服务器 | `e.mcp.name`，缺失时记 `mcp` |
| 耗时 | 毫秒；调用进行中时为 `-1` |
| 成功 | `deny` 或 `isError` 都为失败 |
| 参数 | 事件除 `tool` / `tool_use_id` / `mcp` 外的全部字段，JSON 缩进 |
| 结果 | 返回给模型的文本，截到 4,000 字符，截断处写明「已达存储上限 4,000 字」 |

参数截到 20,000 字符，超出时在截断处写明「已达存储上限 20,000 字」，不再只留裸 `…`。

## 列表

安静页：标题 → 规则线 → 平铺行 → 页脚。每行一个服务器：

```
  MCP · 1 个服务器                                              ← 返回
──────────────────────────────────────────────────────────────────
▸ MCP   12 次  oracle-apex
──────────────────────────────────────────────────────────────────
```

- 第一列是 `MCP` 标签（structural subtle 色），第二列调用次数，名称列吸收剩余宽度。
- 行名是服务器；点行进入该服务器的调用列表。
- 调用列表每行：时间 + `成功` / `失败` + 工具名 + 耗时，最新在前；超过可视行数显示「…还有 N 次」。

## 详情

单次调用是安静页：完整标题按宽度折行，状态行左为 `成功` / `失败`、右为时间；右上角 `← 返回`：

```
  oracle-apex · oracle_query                                     ← 返回
  成功                                                       09:41
──────────────────────────────────────────────────────────────────
时间    11-18 09:41
结果    成功
耗时    320ms

参数
  {
    "query": "SELECT * FROM APP.ORDERS WHERE ..."
  }

结果
  ...
```

显示这次调用的时间、成功/失败、耗时、完整参数与返回给模型的文本；参数与结果按既有上限截断并在截断处写明原因。内容超屏由面板滚动，`← 返回` 固定在视口右上角。

## 上限

最多保留 600 次调用，超出丢弃最早的。
