# 分支区

面板底部的常驻分支栏：显示当前会话所在的仓库、工作区根目录、以及工作区里的各个仓库，各自停在哪个分支、有多少未提交改动。

## 它解决什么

开着的会话可能落在单仓库里，也可能落在一个装着多个仓库的工作区里。不管哪种，切分支之后都该一眼看到「我现在在哪、别的仓库在哪、有没有没提交的东西」，而不用挨个 `cd` 过去 `git branch`。

## 数据从哪来

分支区与 OpenSpec 页签共用同一套「仓库发现」（`hooks/scan.ts` 的 `discoverOf`），两边看到的仓库集合永远一致。

```
<工作区>/                     ← 工作区根：自身是仓库时标「根目录」
├── .git/                     ← 有它就是仓库（根基线）
├── openspec/                 ← 或有它（OpenSpec 仓库）
├── sales-platform/.git/
├── feishu_sale_h5/.git/
└── my-new-tool/.git/         ← 名字不限，有 .git 就列出
```

### 发现的规则

1. **会话目录自身**：`cwd` 有 `.git` 或 `openspec/`，它就是第一行（名称列显示目录名）。
2. **工作区**：从 `cwd` 的上一级开始向上最多找 2 层，第一个「里面装着仓库的目录」就是工作区。
3. **工作区根**：工作区自身是仓库时，作为「根目录」行（`*` 标记）。
4. **兄弟仓库**：工作区下每个含 `.git` 或 `openspec/` 的子目录各一行，按名称排序。
5. 同名路径去重；`node_modules` 跳过。

仓库名**不再**来自写死的白名单：任何带 `.git` 的目录都会出现。

### 每个仓库读什么

- **分支名**：直接读 `.git/HEAD`（不跑进程）。`.git` 是文件（worktree、submodule）时跟随 `gitdir:` 指向的位置再读。
- **未提交改动数**：`git status --porcelain` 的非空行数。

## 分支卡的样子

分支信息是一张**独立的圆角卡片**，标题 `🔀 分支`、右侧摘要为仓库数，嵌在上边线；位于面板底部、主区域卡之下。卡片只画上下圆角边、不画左右竖线：

```
╭─ 🔀 分支 ─────────────────────────────────── · 4 个仓库 ╮
* 根目录          master
| feishu_sale_h5  develop                           +1 [预览]
| old_sales       test                                    
| sales-platform  develop_20_2…001                  +1 [预览]
╰────────────────────────────────────────────────────────────╯
```

- **根目录**行以 `*` 开头（强调色）；兄弟仓库行以 `|` 开头（灰）。
- 目录名列给 14 列（见 [UI 规范](../../UI-SPEC.md) §4.4/§4.5）。
- 分支名**默认色**，干净时不上色（旧版全员 `success` 绿已取消）。
- 分支名超宽时**保留首尾**（`前缀…末7位`）——`develop_20_20261012001` 与 `develop_20_20261021084` 前 20 位相同，只截尾分不开。
- 只有**有未提交改动**的仓库：行尾 `+N` 用 `warning` 色，并出「预览」按钮；干净行的行尾没有按钮。
- 最多显示 5 行仓库，超出以「… 还有 N 个仓库」收尾。
- 点「预览」在面板里显示 `git diff`，可逐文件点开打开。

## diff 预览

diff 列表也是**一张主卡**，仓库与文件数写在卡片标题上：

```
╭─ root ─────────────────────── · 未提交改动 3 个文件 ╮
▸ openspec/changes/archive/x/tasks.md     +40 -0
  src/app.ts                              +12 -3
  assets/logo.png                         二进制
╰─────────────────────────────────────────────────────╯
```

| 看什么 | 怎么来的 |
|---|---|
| 新增 / 删除行数 | 已跟踪文件取自 `git diff`；**未跟踪的新文件**读全文按行数计，删 0 时也写 `-0` |
| `二进制` | 文件含 `\0`：没有文字可显示，行数没有意义 |
| `?` | 文件读不到：行数**未知**，不是 0 |
| 「变更 / 整个文件」 | 文件详情里两种读法：git 的 hunks，或文件现在全文；新文件只有全文 |

**文件详情可以滚到最后一行**：正文不受屏幕高度限制，方向键、`j/k`、PageUp/PageDown、滚轮都能用；标题行和切换标签始终在最上方，`← 返回` 固定在**卡片右上角**。切换「变更 / 整个文件」时正文回到顶部。


## 什么时候刷新

| 时机 | 刷新内容 |
|---|---|
| 会话启动 | 分支 + OpenSpec 列表 |
| 每轮对话结束 | 分支 + OpenSpec 列表 |
| 面板打开期间，**每 5 秒** | 只刷新分支（不重扫 OpenSpec） |

- 轮询用 `$.clock.every(5000)` 起步一次，会话内只有一个轮询器。
- 刷新写状态前先比对内容签名：**内容没变就不写、不重绘**。
- 读取失败时保留上一次的显示，不会突然变空。
- 5 秒的取舍：切分支是秒级操作，最长滞后 5 秒；每轮只读一个 `HEAD` 文件 + 一次 `git status`，开销可接受。

## 行数预算

分支区按 `1 + 仓库数` 行扣减列表可见行数（见 [UI 规范](../../UI-SPEC.md) §4.1）。超过 6 个仓库时只显示前 6 行，末尾追加「… 还有 N 个仓库」。

## 边界情况

| 情况 | 结果 |
|---|---|
| `cwd` 不在任何仓库里 | 只列 `cwd` 的兄弟仓库（工作区取父目录） |
| `HEAD` 是 detached（没有 `ref:`） | 该行不显示 |
| 仓库被删了 | 下一次刷新时该行消失 |
| 工作区下方还有一层目录装着仓库 | 不递归，只找两级 |

## 手工验证步骤

1. 在任意单仓库目录里开会话（例如本项目），打开面板，确认分支区第一行就是当前仓库与它的分支。
2. 在终端 `git checkout -b probe-x`，**不发任何对话**，等 5 秒，确认分支区变成 `probe-x`。
3. `git checkout -` 切回，再等 5 秒确认变回。
4. 在多仓库工作区里开会话，确认根目录与各仓库都列出，名称不是白名单里的也能显示。
5. 随便改一个文件不提交，确认对应行变黄并出现「预览」。
