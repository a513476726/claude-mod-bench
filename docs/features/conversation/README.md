# 对话

本会话里每一轮对话记录成一条：从你的输入（或 AI 的提问）开始，到这一轮结束时的回答、耗时、token、用到的工具与结束原因。

## 它解决什么

「刚刚那轮你到底用了什么、花了多少、为什么停下了」——终端里滚回去看很难找，而且工具调用的成败、token 用量都不在正文里。这个页签把每一轮压成一行，点开看全貌。

## 什么算一轮

| 起点 | 标签 | 触发 |
|---|---|---|
| 你提交输入 | `输入` | `prompt.submit` |
| AI 发起提问 | `提问` | `tool.call` 的 `AskUserQuestion` |
| 续轮（你没打字，引擎自己开的） | `续轮` | `turn.start` 且当前没有进行中的轮 |

- **你提交的输入全部记录**：普通文字、slash 命令、带附件、在 AI 回复中途追加的，都会新开一轮。
- **技能预置文本不算**：以 `Base directory for this skill:` 开头的提交被忽略。
- **前一轮未结束就来了新输入**：前一轮标记为已结束（没有结束原因），新轮开始。
- **子代理的回合不算**：`agentId` 非空的事件全部忽略，只有主循环进对话。
- **失败覆盖原标签**：中断 / 拒绝 / 报错，或本轮有工具失败时，列表标签统一显示 `异常`；原类型仍留在详情的「类型」字段。

## 一轮什么时候结束

引擎的 `turn.complete` 到达时，补全：
- 结束原因：回答 / 中断 / 拒绝 / 报错
- 耗时（毫秒）
- AI 最终可见回答全文
- token 用量：输入 / 输出 / 缓存读 / 缓存写，以及模型 id

中断或报错时引擎不报用量，对应字段显示 `—`，不显示 0。

**已知缺口**：引擎在某些情况下不触发 `turn.complete`（请求没发出去、被拒绝、热重载重置了游标）。这些轮次停在「进行中」，不会伪造为已完成。

## 会话统计

对话页签顶部是一条统计轨道，不再是一张卡片。回答「这次会话到底花了多少、做了什么」：

```
  OpenSpec      对话    MCP    提示音                        6 项
──────────────────────────────────────────────────────────────────
 会话  6 轮 · 2 个模型  入 120K · 出 8K · 缓存读 340K · 缓存写 21K · CTX 62% · 5h 38% · 7d 61% · $0.42
 工具  5 种 · 42 次  ·  命令 17 次
──────────────────────────────────────────────────────────────────
▸ 输入  06:13  把分支状态改成一仓一行
  提问  08:40  按轮次还是按消息逐条？
  异常  09:02  工具调用失败
──────────────────────────────────────────────────────────────────
6 项 · 点行看详情                                          1–4 页签
分支  * 根目录        main                                  +3  预览
```

- **会话行**：轮数、模型数、四项 token；点它下钻到按模型的用量明细。
- **token 单位**：`<1000` 原始数；`1000–999 999` 整数 `K`；`≥1 000 000` 一位小数 `M`；全部向下取整（`999 999` → `999K`，`1 200 000` → `1.2M`）。
- **CTX**：最近一次响应占模型真实上下文窗口的百分比，向下取整；`<70%` 灰、`≥70%` warning、`≥90%` error，超过 100% 照写；引擎还没给出读数时写 `CTX —`。数值与 Claude Code 状态行同源，不是把各轮用量累加。**点 `CTX` 进入上下文构成页**，不会触发压缩。
- **5h / 7d 额度**：最近一次响应的订阅额度窗口，向上取整前先向下取整显示；`<70%` 灰、`≥70%` warning、`≥90%` error。引擎没报某个窗口就省略该窗口，不写 `0%`。
- **成本**：本会话累计美元，取自引擎账本 `usage().cost.usd`，与 `/cost` 同源；始终灰色。3P / gateway 没有账本时写 `$—`，**不写 `$0.00`**，也不按 token 价格表反推。
- **工具 / 命令**两行可下钻。工具是「种类数 · 总调用次数」（种类 = 不同工具名），命令行是 `Bash` 的总调用次数。
- 面板高度 < 20 行时只剩会话行；每模型明细移进「会话」下钻。
- 没有任何已结束的轮次时，写「（暂无用量）」，统计轨道与说明仍在。
- 窄屏收缩：先丢 `$`，再丢 `7d`、`5h`、`CTX`，仍放不下才把 `缓存读 / 缓存写` 缩写为 `读 / 写`。

## 下钻

从统计往下可以一层层点进去。每一层都是**安静页**：完整标题按宽度折行，右上角 `← 返回`（或 `b`）逐层退回：

```
会话统计 ──点会话──▶ 按模型的用量明细
会话统计 ──点工具──▶ 工具分组（Bash 9 次 / Read 4 次 / …）
                       └─点某个工具──▶ 该工具的每次调用（时间 成功/失败 摘要 耗时）
                                         └─点某次调用──▶ 完整参数与结果
会话统计 ──点命令──▶ 每次 Bash 的原文，最新在前 ──▶ 完整参数与结果
```

| 层级 | 标题 | 空态 |
|---|---|---|
| `stats-models` | `会话 · N 个模型 · M 轮` | `（暂无用量）` |
| `stats-tools` | `工具 · N 种 · M 次` | `本次会话没有调用工具` |
| `stats-commands` | `命令 · N 次` | `本次会话没有执行命令` |
| `all:<工具名>` | `<工具> · N 次` | `本次会话没有调用 <工具>` |
| `tool:<轮次>:<工具>` | `<工具> ×N · <该轮输入首行>` | `本轮没有调用 <工具>` |
| 一次调用 | 工具摘要；状态行 `成功` / `失败` + 耗时 | — |

## 上下文构成页

点统计轨道上的 `CTX 62%` 进入「上下文构成」：安静页，没有页签、统计轨道或分支轨道。

```
  上下文构成                                               ← 返回
  opus
──────────────────────────────────────────────────────────────────
  Messages                                              420K · 42%
  Free space                                            380K · 38%
  System prompt                                         120K · 12%
──────────────────────────────────────────────────────────────────
  合计                                                  620K · 62%
  刷新
```

- 数据来自 `$.session.usage({ breakdown: "summary" })`：本地估算，**不发 token-count 请求**；不使用 `full`。
- 一行一个类别，按 token 降序；末尾规则线下是合计行。
- `刷新` 只重读构成，不压缩、不切页签。
- 引擎没有提供 `breakdown` 时，正文只写「引擎未提供构成」，返回仍然可用。
- 类别名按宽度折行，不截断；24 列放不下名称列时，名称与 `token · 占比` 分两行。

## 返回

所有详情与下钻层共用同一个返回入口：**视口右上角**的「← 返回」，`b` 键等价；内容滚动后仍钉在视口右上角、可点击。规则固定：

- 下钻层 → 上一层
- 列表的详情 → 该列表
- 最外层（页签自己的列表）不显示返回

OpenSpec 详情、分支 diff 的文件列表与单文件、提示音页用的是同一个按钮，位置与文案一致。内容超屏时，视口底部右侧显示「第 N/M 行 · ↑↓ 滚动」；全文页（输入/回答）逐行换行，保留缩进，不出现行尾截断。

## 工具归属

AI 在这一轮里调用的每个工具都记到这一轮名下，按**工具名**聚合：

```
Read ×2 · Bash ×1（失败 1）
```

- 只有调用返回后才记一次（不需要先占位再回填）。
- 子代理的工具调用不记。
- `AskUserQuestion` 本身不记为工具（它是新一轮的起点）。
- MCP 工具也计入这里；参数和结果是 MCP 页签的职责，这里只给名字、次数与失败数。

## 详情里的工具可以点

轮次详情底部那行 `Bash ×3 · Write ×4`，每个工具名都是可点的：

- 点 `Bash ×3` → 该轮 3 次 Bash 的具体调用（时间、成败、耗时、命令原文）
- 点其中一条 → 该次调用的完整参数与结果
- 点 `Skill ×N` → 该轮每个技能各调了几次，再点看参数

每轮每个工具最多保留**最近 50 条**调用记录；每条摘要截断到 200 字、参数 2 000 字、结果 400 字。

## 列表

```
<光标:2><标签:5><时间:5><首行摘要:剩余宽度>
▸ 输入  06:13  把分支状态改成一仓一行
  提问  08:40  按轮次还是按消息逐条？
  异常  09:02  工具调用失败
```

- 新的一轮在最上面。
- 标签是行内唯一带色的列：`输入`（accent）/ `提问`（warning）/ `续轮`（subtle）/ `异常`（error）。
- 时间 `HH:MM`；摘要取输入第一行，尾截断。
- 选中行只加 `▸` 与摘要 bold，不改背景、不改标签色。
- 整行可点，进入安静详情页。

## 详情

详情是**安静页**：没有页签、没有统计轨道、没有分支轨道。标题是本轮输入的第一行，按宽度折行；状态行左为标签（`输入` / `提问` / `续轮` / `异常`），右为时间：

```
  把分支状态改成一仓一行                                        ← 返回
  输入                                                     06:13
──────────────────────────────────────────────────────────────────
时间    11-17 06:13
类型    输入
命令    /panel
附件    2 个

输入
  把分支状态改成一仓一行……

回答
  ……

工具
  Bash ×3 · Write ×4

用量
  耗时: 12.3s
  用量: 入 1200 · 出 800 · 缓存读 3400 · 缓存写 210
  模型: claude-opus-5-5
  结束: 回答
```

- 字段是纯文本标签列（8 格，<56 列 6 格），**不带 emoji**；值折行，续行同一列起。
- 分区标题 `输入` / `回答` / `工具` / `用量` 用 accent，无 emoji，正文缩进 2。
- 输入上限 6 行、回答上限半屏；不超就不折；「查看全部」进入安静全屏页，`b` 的层级是全屏 → 详情 → 列表。
- 工具 / 用量不折叠，始终在同一屏内可见。
