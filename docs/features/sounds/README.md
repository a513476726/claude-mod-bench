# 提示音

面板第 4 个页签（快捷键 `4`）：控制会话里的提示音，并可以当场试听。面板不绘制宠物（2026-11-06 起，见 [宠物（已移除）](../pet/README.md)）。

## 它解决什么

原来开关藏在宠物页签里：不知道哪种是开哪种是关，点了几次也没反应，声音还时有时无。现在开关单独一页、状态一眼可见、每行都能试听。

## 页签

一张主卡，卡片标题是 `🔊 提示音`；每行一个开关，「试听」对齐到卡片右内侧同一列：

```
╭─ 🔊 提示音 ───────────────────────────────────── · 4 项 ╮
─ 开关
▸ 🔊 开  总开关                                  ▶ 试听
  🔊 开  需要决策                                ▶ 试听
  🔇 关  任务完成                                ▶ 试听
  🔊 开  任务异常                                ▶ 试听
╰────────────────────────────────────────────────────────╯
```

| 行 | 什么时候响 |
|---|---|
| 总开关 | 关掉后**任何**提示音都不播 |
| 需要决策 | 模型用 `AskUserQuestion` 提问时 |
| 任务完成 | 一轮对话正常结束（回答）时 |
| 任务异常 | 一轮对话以报错、中断、拒绝结束，或子代理之外的非正常结束时 |

## 怎么用

- **点整行** = 切换这一项，立刻生效，下一次事件就按新状态播放。
- **点「▶ 试听」** = 当场播放这一项的声音，不受这一项开关限制——用来确认音频链路正常。总开关行的试听播 `sounds/done.wav`。
- 总开关关着时，试听也不出声。

## 为什么以前「点了没反应、声音时有时无」

1. 开关行在 `Button.onPress` 和 `ui.press` 钩子里**各写了一次**，点一下翻两次，看起来没变。现在只在 `onPress` 写一次。
2. 播放读的是另一份设置对象，且一整条 `feedPet` 调用链任一环节失败就整条静默。现在 `notify` 直接读 `sounds`，失败只写日志，不影响对话。

## 声音文件

`sounds/decision.wav`、`sounds/done.wav`、`sounds/error.wav`，由面板目录下的 `sounds/` 提供。

## 手工验证

1. 按 `4` 切到提示音页，确认四行开关与「▶ 试听」都在。
2. 点「任务完成」行：状态在 `[开]` / `[关]` 之间切换，点一次只变一次。
3. 点「▶ 试听」：立刻听到声音。
4. 关掉总开关，再点任意「▶ 试听」：没有声音。
5. 打开总开关，让一轮对话正常结束：听到完成音；把面板关掉再开，设置仍在。
