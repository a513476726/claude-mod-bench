# OpenSpec 变更追踪 - 变更扫描与分段

---

## 1. 背景与目标

### 1.1 功能描述

扫描工作区各仓库的 `openspec/changes/`，把每一处变更按状态分成五段展示，一行一条，点开看任务进度、需求号、作者与未完成项。

### 1.2 使用场景

- 同时推进多个需求时，确认「哪个变更做到哪、哪个归档没归干净」。
- 归档前检查已归档的变更里是否还有没勾完的任务。

### 1.3 功能范围

**包含：**

- 扫描进行中的变更与 `archive/` 下的已归档变更
- 按状态分五段：进行中、待归档、归档异常、已归档、无任务清单
- 每段的展开 / 折叠与计数
- 单条变更的详情：进度、需求号、开发、修改时间、未完成任务原文

**不包含：**

- 修改 `tasks.md` 或任何变更文件
- 归档操作（由 OpenSpec CLI 负责）

---

## 2. 业务流程

```text
会话启动 / 每轮对话结束
    ↓
用与分支区相同的仓库发现，得到要扫描的目录
    ↓
逐目录读取 openspec/changes/
    ├── 子目录名为 archive → 读其下每个已归档变更
    └── 其他子目录 → 读作进行中变更
         ↓
    数 tasks.md 的 - [x] / - [ ]
    从 proposal.md 取「需求号：」
    取该目录的 git 作者
         ↓
    按修改时间倒序排列，按状态分五段
```

---

## 3. 业务规则

| 规则 | 说明 |
| --- | --- |
| 扫描范围 | 与分支区共用 `discoverOf` 的仓库集合；工作区根自身若含 `openspec/` 也纳入 |
| 进度 | `tasks.md` 中 `- [x]` 计已完成、`- [ ]` 计总数；没有 `tasks.md` 则归入「无任务清单」 |
| 需求号 | 从 `proposal.md` 的文字 `需求号：xxx` 提取，没有则详情里显示未写 |
| 作者 | 变更目录被 git 跟踪时取 `git log` 作者（最多 5 位）；未跟踪时取 `git config user.name` |
| 修改时间 | 变更目录本身、其中每个文件与一层子目录的最大 mtime |
| 归档日期 | 归档目录名以 `YYYY-MM-DD-` 开头时取该日期 |
| 分段判定 | 无 `tasks.md` → 无任务清单；已归档且未做完 → 归档异常；已归档且做完 → 已归档；未归档且未做完 → 进行中；未归档且做完 → 待归档 |
| 排序 | 五段顺序固定；段内按修改时间倒序；最新的一条带 `*` 标记 |
| 默认展开 | 只展开「进行中」，其余四段折叠 |
| 扫描起点 | 固定为**会话起始目录**，不随会话中途的 cwd 变化；分支栏仍跟随实况 cwd |
| 读取失败 | 一个仓库读不到只跳过它；全都没读到才算失败。失败时**保留上一次的列表**并标注「（刷新失败，显示上次结果）」 |
| 空态三种 | 有变更 → 列表；仓库都在但没有变更 → 「还没有读到任何 openspec/changes。」；一个仓库都没扫描（搁置空间等）→ 「未扫描任何仓库：<原因>」 |
| 刷新周期 | 面板打开期间每 5 秒重扫一次，与分支栏各自一个周期 |
| 内容未变不重绘 | 列表签名一致时不写状态 |

## 4. 权限与状态

### 4.1 权限

| 角色 | 权限 | 说明 |
| --- | --- | --- |
| 使用者 | 查看、展开/折叠 | 只读 |

### 4.2 状态

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| 进行中 | 未归档，任务未做完 | 点开看剩余任务原文 |
| 待归档 | 未归档，任务已做完 | 点开看详情 |
| 归档异常 | 已归档，但任务未做完 | 点开看剩余任务 |
| 已归档 | 已归档且做完 | 点开看详情 |
| 无任务清单 | 没有 `tasks.md` | 点开看详情 |

## 5. 方案要点

### 5.1 前端

列表行固定列宽：进度（右对齐）、时间、仓库、名称；名称尾截断。分段标题并列成一行，点标题切换展开/折叠，折叠时保留标题与计数。

### 5.2 后端

`hooks/scan.ts` 的 `scan()` 遍历仓库、读取变更、组装 `SpecChange`；`groupOf()` 决定分段；`changeOf()` 负责单个变更的读取与截断。

### 5.3 架构 / 依赖

只读本地文件与 git 命令。

## 7. 接口设计

### 7.1 接口列表

无（无 HTTP 接口）。

### 7.4 关键字段

变更记录的字段（来自 `SpecChange` 类型）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 是 | 变更目录名（归档的含日期前缀） |
| `repo` | string | 是 | 变更所在的仓库目录名 |
| `done` / `total` | number | 是 | `tasks.md` 中已勾选 / 总任务数 |
| `hasTasks` | boolean | 是 | 是否存在 `tasks.md` |
| `files` | string[] | 是 | 变更目录下的文件名 |
| `mtime` | number | 是 | 最后一次修改时间（epoch ms） |
| `isArchived` | boolean | 是 | 是否来自 `archive/` |
| `needNo` | string | 是 | `proposal.md` 中的需求号，无则为空 |
| `archivedOn` | string | 是 | 归档目录名开头的日期 |
| `authors` | string[] | 是 | git 作者，最多 5 位 |
| `open` | string[] | 是 | 未勾选的任务原文 |

---

## 7.5 筛选

| 规则 | 说明 |
| --- | --- |
| 入口 | 列表上方一行：`筛选 仓库：… · 时间：…`，各自一键循环切换 |
| 仓库 | 「全部」与本次扫描到的每个仓库 |
| 时间 | 全部 / 今天 / 近 7 天 / 近 30 天；「今天」为当天 0 点之后 |
| 叠加 | 两个条件同时生效 |
| 计数 | 分段计数随筛选变化；没有内容的分段不显示标题 |
| 保持 | 刷新、切换页签不重置筛选 |
| 清除 | 任一筛选生效时出现「清除」，一键回到全量 |

## 10. 可测验收标准

| 编号 | 前置条件 | 操作 / 触发 | 预期结果 | 优先级 |
| --- | --- | --- | --- | --- |
| AC-01 | 工作区含 1 个进行中、1 个待归档、1 个无清单、归档里 1 个干净 1 个异常 | 打开 OpenSpec 页签 | 分段计数：进行中 1、待归档 1、归档异常 1、无任务清单 1，已归档段无标题 | P0 |
| AC-02 | 同上 | 点「进行中」标题 | 该段的行收起，标题与计数仍在 | P0 |
| AC-03 | 某变更 | 点开该行 | 详情显示需求号与未完成任务的原文，而不只是「欠 N 项」 | P0 |
| AC-04 | 列表被面板高度截断 | 查看页脚 | 页脚写「N/M 项 · 点行看详情」 | P0 |
| AC-05 | 已归档变更仍有未勾任务 | 打开页签 | 该变更归入「归档异常」 | P0 |
| AC-06 | 变更目录未被 git 跟踪 | 点开详情 | 作者取 `git config user.name` | P1 |
| AC-07 | 列表比可见行多 | 操作 | 选中位置不越过列表边界 | P1 |
| AC-08 | 会话起始目录与当前 cwd 不同 | 触发刷新 | 仍扫描起始目录，列表不漂移 | P0 |
| AC-09 | 会话起始目录带搁置标记 | 打开页签 | 显示「未扫描任何仓库：<原因>」，不是空态 | P0 |
| AC-10 | 所有 `openspec/changes` 都读不到 | 触发刷新 | 保留上一次列表并标注刷新失败 | P0 |
| AC-11 | 面板打开，不发对话，勾选一项任务 | 等一个周期 | 该变更进度与分段更新 | P0 |
| AC-12 | 打开某变更详情后列表刷新 | 自动刷新 | 选中仍是同一变更 | P1 |
| AC-13 | 选定一个仓库 | 查看列表与分段计数 | 只显示该仓库，计数随之变化 | P0 |
| AC-14 | 选择「近 7 天」 | 查看列表 | 只显示最近 7 天内修改的变更 | P0 |
| AC-15 | 有筛选时按「清除」 | 查看列表 | 回到全量 | P1 |
