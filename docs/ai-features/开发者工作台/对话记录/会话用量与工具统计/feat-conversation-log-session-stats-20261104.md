# 对话记录 - 会话用量与工具统计

---

## 1. 背景与目标

### 1.1 功能描述

对话页签顶部给出整场会话的用量与工具使用全貌：每个模型花了多少 token、一共调了多少次工具、跑了多少条命令。

### 1.2 使用场景

- 长会话结束时复盘「这次花了多少、主要花在哪个模型上」。
- 想快速确认「这次会话主要在用哪些工具」。

### 1.3 功能范围

**包含：**

- 按模型分组的输入 / 输出 / 缓存读 / 缓存写 token 与合计
- 工具种类数与总调用次数
- 命令（`Bash`）执行次数

**不包含：**

- 跨会话累计（只统计当前保留的轮次）
- 费用金额换算
- 子代理单独统计

---

## 2. 业务流程

```text
读取本会话保留的轮次
    ↓
逐轮取 token 用量（模型、输入、输出、缓存读、缓存写）
    ↓
按模型分组求和，再求全部合计
    ↓
逐轮取工具调用（按工具名计次）
    ↓
汇总工具种类数、总次数、Bash 次数
    ↓
画在对话页签顶部
```

---

## 3. 业务规则

| 规则 | 说明 |
| --- | --- |
| 统计范围 | 仅统计当前 `turns` 中保留的轮次；超出保留上限被淘汰的轮次不计入 |
| 模型分组 | 按 `usage.model` 分组，同一模型的多个轮次求和，按轮数降序 |
| 未报模型 | `usage.model` 为空时归为「未知模型」 |
| 无用量 | 没有任何已结束轮次时显示「（暂无用量）」 |
| 工具种类 | 不同工具名的个数 |
| 命令次数 | 工具名为 `Bash` 的调用次数 |
| 空会话 | 无工具调用时显示「工具 0 种 · 0 次」 |
| 小面板 | 面板高度小于 20 行时只显示第一行模型摘要 |

## 5. 方案要点

### 5.1 前端

对话页签顶部固定区块：标题「─── 会话」、最多 4 行模型（按轮数降序）加一行合计、「工具 N 种 · M 次」与「命令 K 次」两行可点条目。统计区占用 4 + 模型数 行，从列表可见行数中扣除。

### 5.2 后端

`hooks/conversation.ts` 的 `statsOf(turns)` 纯函数完成汇总；`hooks/items.ts` 的 `statsLines()` 把结果格式化为展示文本。

### 5.3 架构 / 依赖

不依赖网络；数据全部来自本地保留的轮次记录。

---

## 6. 影响范围

- 对话页签的可见行数（统计区占用）
- 与其他面板区域的排版预算

### 6.2 兼容性

`decisions` 状态形状升级，旧值在升级时丢弃。

---

## 7. 接口设计

无 HTTP 接口。

### 7.4 关键字段

统计结果字段（来自 `SessionStats`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `models[].model` | string | 是 | 模型 id |
| `models[].turns` | number | 是 | 该模型回答的轮数 |
| `models[].input/output/cacheRead/cacheWrite` | number | 是 | 四项 token 之和 |
| `total` | object | 是 | 全部模型的四项合计 |
| `toolKinds` | number | 是 | 不同工具名的个数 |
| `toolCalls` | number | 是 | 工具调用总次数 |
| `commandCalls` | number | 是 | `Bash` 调用次数 |

## 10. 可测验收标准

| 编号 | 前置条件 | 操作 / 触发 | 预期结果 | 优先级 |
| --- | --- | --- | --- | --- |
| AC-01 | 三轮分别由两个模型回答（opus 两轮、haiku 一轮） | 打开对话页签 | 显示两行模型 + 一行合计，合计等于所有轮次之和 | P0 |
| AC-02 | 会话共调用 Bash 5 次、Read 3 次、Write 1 次 | 打开页签 | 显示「工具 3 种 · 9 次」 | P0 |
| AC-03 | 会话刚开始，无已结束轮次 | 打开页签 | 模型位显示「（暂无用量）」 | P0 |
| AC-04 | 无任何工具调用 | 打开页签 | 显示「工具 0 种 · 0 次」 | P1 |
| AC-05 | 面板高度为 12 行 | 打开页签 | 只显示一行模型摘要 | P1 |
