# bench UI 规范

> Claude Code 开发者面板的界面设计标准。所有界面改动以此为准，不符合的实现视为缺陷。
>
> **分层原则**：本文分「引擎约束」（不可协商，违反即加载失败或错位）与「项目决策」（我们的选择，可迭代，改动需更新本文）。两者不混写。

---

## 0. 设计原则

1. **一列一义**：每个字段占固定列，各列独立截断，永不跨列侵占。所有行左缘对齐成一条线。
2. **字形恒定**：行首槽位宽度固定，符号宽度确定。不因内容变化而移位。
3. **颜色只标状态，不标装饰**：一屏最多 3 种彩色。结构性元素（框线、分隔）一律灰阶。

**定位**：表格式对齐的信息流 —— 一行一件事，固定列，`git log --oneline` 的密度 + 表格的扫读性。

---

## 1. 引擎约束（不可协商）

以下来自 `claude-code.d.ts` 与本机实测，**违反会直接出问题**，不是风格偏好。

### 1.1 字符宽度

| 约束 | 说明 |
|---|---|
| **禁用 East Asian Ambiguous 字符** | `●` `○` `★` `⚠` `▶` `▼` 在 CJK 终端可能占 2 格。UAX #11 原文：「不打算给现代终端在未做适配的情况下直接使用」 |
| **禁用 emoji** | 宽度实测不一致，kitty/tmux 各有例外 |
| **禁用 Nerd Font 图标** | 用户未装字体即成豆腐块，且无法探测 |
| **安全符号集** | 见 §5，全部单格宽度 |
| **中文占 2 格** | 任何补空格、算宽度都必须按显示宽度而非字符数 |

### 1.2 组件能力边界

| 组件 | 能做 | 不能做 |
|---|---|---|
| `Button`（默认） | 带 `[ label ]` 边框、`variant="primary"` 强调、`hotkey` | 自定义颜色 |
| `Button`（`plain`） | 无边框、children 任意树、children 内 `Text` 可上色 | `hotkey` 会渲染成 `1: label` 前缀 |
| `Text` | `color` / `backgroundColor` / `weight` / `dimColor` / `wrap` / `tabular` | — |
| `Box` | `flexDirection` / `flexGrow` / `padding` / `borderStyle` / `gap` | **`marginTop` 在 Pane 内不生效** |

**结论**：
- 列表行、分区标题**必须用 `plain`**，否则被 `[ ]` 撑成按钮外观
- `plain` 的 `label` 只是无障碍名，**实际绘制看 children**
- 需要键盘热键的位置（页签）用**默认 Button**，接受 `[ ]` 边框——它反而是页签的视觉语言

### 1.3 布局

| 约束 | 说明 |
|---|---|
| 主动打开的面板需 **≥144 列**才停靠 | 窄屏下挂起不绘制（`isPlaced: false`） |
| 主屏模式（tmux / `NO_FLICKER=0`）**不 dock 面板** | 宽度再大也无用 |
| 列宽优先级（Ratatui 标准） | `Min > Max > Length > Percentage > Ratio > Fill` |
| **只留一个 Fill 列** | 多个弹性列会互相挤压，且 `Length`+`Percentage` 混合时 Percentage 列会被挤到 0 且不显示省略号 |

## 2. 间距体系（4 的倍数栅格）

基准单位 **4 格**。所有间距只能是 0 / 2 / 4 的倍数。

| 间距类型 | 值 | 用于 |
|---|---|---|
| `GAP_INLINE` | 2 | 行内字段之间 |
| `GAP_GROUP` | 4 | 分区标题内各组之间 |
| `GAP_SECTION` | 1 行 | 分区之间（空行） |
| `GAP_FRAME` | 0 | 行与行之间（无空行） |

**禁止**：3、5、7 这类非 4 倍数的间距。禁止用 `marginTop`（Pane 内无效），分区间距用空 `<Text> </Text>`。

## 3. 布局结构

### 3.1 垂直骨架（自上而下）

```
┌─────────────────────────────────────┐
│ 页签行                      1 行     │  TabBar
│ 分区标题行                  1 行     │  SectionBar（仅分组页）
│                                     │
│ 列表区                     N 行     │  List（Fill，吸收剩余高度）
│                                     │
│ 页脚                        1 行     │  Footer
│ 分支区                    1+M 行     │  BranchBar
└─────────────────────────────────────┘
```

**行数预算**：`列表可见行数 = bodyRows - 页签(1) - 分区标题(1) - 页脚(1) - 分支区(1+仓库数)`

### 3.2 水平列定义

**列表行**（OpenSpec 页）：

```
<ind:2><done:7><gap:2><age:4><gap:2><repo:14><gap:2><name:Fill>
> 13/16     6d    old_sales          fix-signmanager-full-down-payment-20260920
```

| 列 | 宽 | 对齐 | 截断 |
|---|---|---|---|
| `ind` 光标槽 | 2 | 左 | — |
| `done` 进度 | 7 | 右 | — |
| `age` 时间 | 4 | 右 | — |
| `repo` 仓库 | 14 | 左 | **中截断**（保首尾） |
| `name` 名称 | Fill | 左 | **尾截断** |

**为什么进度在前**：`13/16` / `28/32` 数字右缘对齐，竖着扫能直接比较剩余量。

**为什么 repo 中截断**：`sales-platform` 与 `sales_platform_web` 差异在中段偏后，尾截断会截掉区分点。

## 4. 组件规范（6 个基础组件）

每个组件给：**结构模板 / 变体 / 尺寸 / 颜色 / 反例**。

### 4.1 TabBar 页签栏

**用途**：切换顶层功能域。

**结构**：
```
◉ [OpenSpec]  [  决策  ]  [  MCP  ]  [  提示音  ]
  ↑ 选中：蓝字+加粗+实心点    ↑ 未选中：dimColor
```

| 状态 | 实现 | 外观 |
|---|---|---|
| 选中 | `plain` `Button` + children `<Text color="claude" bold>◉ [名称]</Text>` | 蓝字加粗 + 实心点 |
| 未选中 | 默认 `Button` + `dimColor` | 灰色 `[ 名称 ]` |

**规则**（已实测定稿）：
- 选中态用**前景色变色 + 加粗 + `◉` 前置点**，**不用背景色**（背景块比列表还重）
- 选中态显示 `◉ [名称]`，**不显示热键编号**（`plain`+`hotkey` 会自动画 `1:` 前缀，读起来和名称连在一起）
- 未选中显示 `[ 名称 ]`，热键仍然生效（按 `1`-`4` 可切换）
- 点号用 **`◉` U+25C9（EAW=Neutral）**，不用 `●`（Ambiguous）或 `·`（Ambiguous）
- 页签数量 ≤ 6

**反例**：❌ 用 `backgroundColor` 做选中（视觉过重）❌ 选中态显示 `1:`（与名称粘连）❌ 用 `·`（读起来像 `·1`）

---

### 4.2 SectionBar 分区标题栏

**用途**：一个页面内的分组，**所有分区标题并列在一行**。

**结构**：
```
▾ * 进行中 7   ▸ o 待归档 5   ▸ ! 归档异常 7   ▸ + 已归档 12   ▸ . 无清单 4
```

| 部分 | 符号 | 颜色 | 宽 |
|---|---|---|---|
| 展开/折叠 | `▾` / `▸` | `inactive` | 1 |
| 状态标记 | `*` `o` `!` `+` `.` | 见 §5.2 | 1 |
| 名称 | 文字 | 灰阶（异常除外） | 固定 |
| 计数 | 数字 | 异常=`error`，其他=`subtle` | — |
| 组间 | — | — | 3 空格 |

**规则**：
- **必须并列成一行**，不允许多行——5 个分区各占一行会吃掉 10+ 行
- 超过宽度时**从右侧丢弃**低优先级分区（优先级按 `GROUP_ORDER`）
- 折叠时整组只剩标题，展开时标题下方接行列表
- 整个标题是 `plain` Button，点击切换展开

**反例**：❌ 每个分区占一行 ❌ 分区之间加空行（行数翻倍）

---

### 4.3 List / Row 列表行

**用途**：承载一条记录。

**结构**：
```
<光标:2><状态:1><空格><列1><gap><列2><gap>...<列N:Fill>
>! 13/16     6d    old_sales          fix-signmanager-full-down-payment-20260920
```

| 槽位 | 内容 | 规则 |
|---|---|---|
| 光标 | `> ` 或 `  ` | 仅当前选中行显示 `>`，颜色 `claude` |
| 状态 | `!` / `*` / 空格 | 异常 `error`、最新 `warning`、其余 `subtle` |
| 内容列 | 见 §3.2 | 各列固定宽，`Fill` 列最后 |

**变体**：
| 变体 | 特征 |
|---|---|
| 普通行 | 前景 `text` |
| 警示行 | 状态槽 `!`，颜色 `error` |
| 最新行 | 状态槽 `*`，颜色 `warning` |
| 弱化行 | `dimColor`（已归档、无清单） |

**规则**：
- **必须 `plain`**，不给 `hotkey`（`plain`+hotkey 会出现 `1:` 前缀）
- 整行可点击，点击进入详情
- 长度超出时**最后一列尾截断**，其他列各自独立截断

**反例**：❌ 用 `[ ]` 包住行（变成按钮，混淆层级）❌ 列宽随内容浮动（无法纵向扫读）

---

### 4.4 Footer 页脚

**结构**：
```
11/35 项 · 点行看详情          [ 展开全部 ]
```

| 部分 | 内容 | 颜色 |
|---|---|---|
| 左 | `<可见数>/<总数> 项 · <操作提示>` | `subtle` |
| 右 | 操作按钮（默认 Button） | — |

**规则**：
- 提示文案 ≤ 20 字，只写「怎么用」，不写「是什么」
- 显示数为 `可见/总数`，**不能只显示总数**——用户需要知道还有多少没看到
- 右侧按钮最多 1 个

**反例**：❌ `11/11 项 · 共 35 · 点分区标题收起 · 点一行看详情`（冗余，且 `11/11` 让人以为看全了）

---

### 4.5 BranchBar 分支栏

**用途**：显示工作区各仓库的当前分支。

**结构**：
```
-- 分支 -------------------------
* 根目录        master
| old_sales     develop_20_20261021084
| sales-plat…   develop_20_20261012001
```

| 部分 | 规则 |
|---|---|
| 分隔线 | `--` + 填充 `-` 到面板宽度，`inactive` |
| 根目录标记 | `*`，`suggestion` 色 |
| 子仓库标记 | `|`，`inactive` 色 |
| 名称列 | 固定 15 格，超出中截断 |
| 分支列 | 剩余宽度，**保留首尾**（前缀 + `…` + 末 7 位） |

**为什么保留末 7 位**：`develop_20_20261012001` 与 `develop_20_20261021084` 前 20 位相同，只截尾无法区分。尾部才是需求号的区分点。

**规则**：一仓一行，**绝不横排**（横排 80 列必挤成一团）。

---

### 4.6 Detail 详情

**结构**：两列对齐，标签固定 8 格。

```
名称        feat-paydetail-bound-flows-biztype-20261023
仓库        sales-platform
状态        待归档
任务        10/10
需求号      （proposal.md 未写）
文件        tasks.md  proposal.md
修改        11-02 14:32（1d 前）

[ ← 返回列表 ]
```

| 部分 | 规则 |
|---|---|
| 标签列 | 8 格，`subtle` 色 |
| 值列 | 从第 10 格起，`text` 色（长值截断） |
| 空行 | 标签组之间 1 行 |
| 返回按钮 | 默认 Button，`hotkey="b"` |

## 5. 文字与颜色规范

### 5.1 字重体系（终端实际两档，已实测）

> **重要**：设计上的四档在终端**做不到**。引擎原文：「The terminal draws `semibold` and `bold` as bold」——`semibold` 与 `bold` 渲染完全相同，`medium` 与 `regular` 也分不出来。

**实际可用只有两档**：

| 档位 | `weight` | 用于 |
|---|---|---|
| **重** | `bold` | 页签选中、详情页标签 |
| **常规** | 缺省 | 其余全部 |

**层级不靠字重，靠颜色**（实测结论：用户反馈「加粗不明显」）。分区标题的层级用 `toneOf()` 的颜色表达，不用 `weight`。

**禁止**：在 `dimColor` 上再叠加 `weight`（渲染不可预测）。

### 5.2 颜色映射（主题色 + 5 色分区，已定稿）

**主题色（Accent）＝ `claude`** —— Claude Code 品牌色，含义「当前/活跃」。**所有选中态一律用它**：

| 位置 | 用法 |
|---|---|
| 页签选中 | `color="claude"` + `bold` |
| 分区「进行中」 | `toneOf` → `claude` |
| 列表行光标 `>` | `color="claude"` |
| 横条进行中计数 | `color="claude"` |

跟随用户主题自动变色，不硬编码。

**分区色板（5 色）**：

| 分区 | ThemeKey | 含义 |
|---|---|---|
| 进行中 | `claude` | 当前在干 |
| 待归档 | `warning` | 等着处理 |
| 归档异常 | `error` | 出问题 |
| 已归档 | `success` | 已闭环 |
| 无任务清单 | `subtle` | 信息量最低 |

**灰阶**：正文缺省 / 弱化 `subtle` / 结构符号 `inactive` / 已完成内容 `dimColor` / 反色前景 `inverseText`

**规则**：同一语义全项目同色；每行最多 1 个彩色元素；禁止 hex。

## 6. 字符集（安全符号）

单格宽度已验证。**加入新符号前必须确认 EAW 属性为 Neutral 或 Narrow。**

| 符号 | 含义 | 位置 |
|---|---|---|
| `◉` | 页签选中 | 页签栏 |
| `▸` `▾` | 折叠 / 展开 | 分区标题 |
| `>` | 光标位置 | 行首 |
| `*` | 进行中 / 最新 | 状态槽、分区标记 |
| `o` | 待处理 | 状态槽、分区标记 |
| `!` | 异常 | 状态槽、分区标记 |
| `+` | 已完成 | 分区标记 |
| `.` | 无任务清单 | 分区标记 |
| `|` | 竖线 | 分支区 |
| `-` | 分隔线 | 分支区、页脚 |
| `←` `→` | 返回 / 前进 | 按钮 |

**禁用**（East Asian Ambiguous）：`●` U+25CF `○` U+25CB `★` U+2605 `⚠` U+26A0 `▶` `▼` `■` `◆` `·` U+00B7 `•` U+2022

**安全替代对照**：`●`→`◉`(U+25C9) / `·`→`◉` / `○`→`o` / `★`→`*`
**禁用**：emoji、Nerd Font 图标、Powerline 字形

## 7. 状态规范

| 状态 | 视觉表达 | 说明 |
|---|---|---|
| 正常 | 默认前景色 | 无额外标记 |
| 进行中 | `*` + `claude` | 蓝 |
| 待处理 | `o` + 灰 | 不用黄（留给最新） |
| 异常 | `!` + `error` | 红，唯一允许的告警色 |
| 已完成 | `+` + `dimColor` | 不用绿 |
| 无数据 | `subtle` 文字 | 只显示「还没有 X」 |
| 加载中 | 不显示进度条 | 引擎无此组件，靠内容出现 |

**空态文案规范**：`<还没有 X>。` 一句话，句号结尾，不写操作指引（操作指引放页脚）。

## 8. 反例清单

以下写法**一律视为缺陷**：

| # | 反例 | 原因 |
|---|---|---|
| 1 | 列表行用默认 `Button` | `[ ]` 边框把层级吃光 |
| 2 | 每个分区占一行标题 | 5 个分区吃掉 10+ 行 |
| 3 | `padEnd` 补齐中文字段 | 中文占 2 格，列会错位 |
| 4 | 用 `● ○ ★ ⚠` | EAW Ambiguous，可能占 2 格 |
| 5 | 多个 Fill 列 | 互相挤压，宽度不可预测 |
| 6 | `marginTop` 做间距 | Pane 内不生效 |
| 7 | 硬编码 hex 颜色 | 不跟随用户主题 |
| 8 | 一屏超过 3 种彩色 | 注意力分散 |
| 9 | 页脚只显示总数 | 用户不知还有多少没看到 |
| 10 | 详情页无返回按钮 | 键盘无法退出 |
| 11 | `plain` + `hotkey` | 渲染出 `1: label` 前缀 |
| 12 | 分支横排 | 80 列必然挤成一团 |

## 9. 落地检查清单

改动界面后逐条核对：

1. [ ] 列表行、分区标题用 `plain`，且无 `hotkey`

3. [ ] 所有间距是 0 / 2 / 4 的倍数
4. [ ] 没有 `marginTop`，分区间距用空 `<Text>`
5. [ ] 所有符号在 §6 白名单内

8. [ ] 列表只有一个 Fill 列
9. [ ] 页脚显示 `可见/总数`

## 附：与引擎的关系

本规范中 §1 是引擎强加的，我们只能遵守；§2-§8 是我们的选择，可以改，但**改动必须同步更新本文**。

引擎版本变化时（当前 2.1.317），§1 需要重新核对 `.claude-plugin/types/claude-code/index.d.ts`。
